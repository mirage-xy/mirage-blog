## 0. 一句话说明

一个用 **Go + SQLite** 写的个人多板块网站。**有权限体系和分享机制**：
站长登录后看到的是完整后台（可编辑、可生成分享链接），访客打开看到的是干净的公开内容；
通过**分享链接可以把私密内容分享给指定的人。内容改动即时生效**，没有构建环节。

身份只有两级：**站长**（你）和**访客**（任何人，不注册）。

## 1. 背景与目标

### 1.1 起点

服务器 `119.91.202.143` 上曾经跑过一个 Astro 静态博客，已经下线并删除。这套 Go 的方案是从零重写的：上一轮会话留下的文章、插画和旧代码都是那轮编出来的东西，全部作废，只保留设计思路和技术选型。文档里写的每个表、每个接口都要亲手写出来。

### 1.2 目标

| # | 目标 | 说明 |
|---|---|---|
| G1 | **多板块个人站** | 先做三个板块：手记（技术笔记）、关于、留言。新增板块是配置级操作，后台插一行记录，不改代码。 |
| G2 | **权限体系** | 两级身份：站长（全权）加访客（只读公开内容）。权限判定收口到一个纯函数。 |
| G3 | **分享机制** | 任何内容可生成带权限的分享链接，可设有效期、访问密码、最大次数，能分享私密内容。这是“我分享出去别人看到的不一样”的实现方式。 |
| G4 | **附件（本期预留）** | 数据结构和接口先留好：文章和板块可挂附件，附件受同一套权限保护。本期不实现上传，等真有东西要存再说。 |
| G5 | **可编辑且即时生效** | 登录后台改内容，刷新前台就是新的。没有构建流程。 |
| G6 | **视觉重做** | 放弃古板风，做低饱和、大留白、纸感、柔和圆角的日常阅读风格。不依赖任何插画，纯排版和配色撑起来。 |
| G7 | **轻量** | 2C2G 的老机器（内存 1.9G，还要跑 tiktok 站、Trilium、NPM、nginx-ui、vsftpd）。新服务常驻内存目标 < 40 MB。 |
| G8 | **可学习** | 这是本项目存在的核心理由。代码要读得懂、改得动、能学到东西，不是跑起来就行。 |

### 1.3 非目标

- 不做注册、不做普通用户，只有站长和访客
- 不做附件上传，只留接口，见 G4
- 不做多人实时协作编辑
- 不做支付、订阅、会员等级
- 不做“登录后才能看”的付费墙，私密内容靠分享链接控制
- 不做水平扩展或多机部署，单机单文件 SQLite
- 不做前端框架、不做构建链、不引外部 CDN
- 不做插画、配图和相册这类需要素材的内容，文章要配图就用截图

### 1.4 这个项目的“学习价值”在哪

纯静态站能学到的东西几乎没有，改个文案都是改文件。而这个项目覆盖了 Web 后端最核心的一整条链路：

| 阶段 | 会学到什么 |
|---|---|
| HTTP 路由 | Go 1.22+ 的 `ServeMux` 模式匹配、方法路由、路径参数、404/405 处理 |
| 模板 | `html/template` 的自动转义机制，以及“模板只管渲染、逻辑全在 Go 侧”的边界怎么划 |
| 数据层 | `database/sql`、连接池、WAL 模式、事务边界、为什么 SQLite 单写者要这样配 |
| 认证 | 密码哈希（bcrypt）、会话表、Cookie 签名、CSRF 双提交校验 |
| 权限 | “谁在什么资源上能做什么”的判断怎么落地、为什么只能写在一个纯函数里 |
| 文件 | multipart 上传、流式落盘、路径穿越防护、附件的访问控制 |
| 性能 | 首屏体积、gzip、字体子集化、缓存头、数据库查询计划 |
| 运维 | systemd、Nginx 反代与缓存、备份与回滚、日志 |

排期原则：每个里程碑结束时，你都要能说清“这一阶段新增了哪个概念、我踩了什么坑、怎么修的”。

## 2. 技术选型

### 2.1 后端

| 项 | 选择 | 理由 |
|---|---|---|
| 语言 | **Go 1.25+** | 单二进制、内存低、部署简单；用户明确要求 Go |
| HTTP | 标准库 `net/http` | Go 1.22+ 的 `ServeMux` 已支持方法 + 通配符路由，**不需要第三方框架**。学习价值最高——能看清 HTTP 到底怎么走的 |
| 模板 | 标准库 `html/template` | 自动转义防 XSS；且能直观理解“模板不是编程语言” |
| Markdown | `github.com/yuin/goldmark` | Go 生态事实标准，GFM 支持完善 |
| 数据库 | **SQLite** via `modernc.org/sqlite` | 纯 Go 实现、**无需 CGO/编译器**（服务器不保证有 gcc）；BSD-3-Clause；当前 v1.61.0 |
| 会话 | **自建**（`sessions` 表 + 签名 Cookie） | 不引第三方 session 库——这块是自己学鉴权最好的素材 |
| 密码哈希 | `golang.org/x/crypto/bcrypt` | 标准做法 |
| 权限判定 | **自建**（`internal/perm`） | 规则简单但值得自己写一遍，别用现成 RBAC 库。**两级身份也用同一套模型**——以后加用户只是多几条数据 |
| 静态资源 | **Nginx 直出** | 发布期生成到 `static/public/`，Nginx 长缓存直出 `/assets/`；Go 进程不碰静态文件 |
| 模板与迁移 | `embed.FS` | `templates/` 和 `migrations/` 打进二进制，部署只拷一个文件 |
| 附件存储 | **磁盘文件 + SQLite 元数据** | 不塞进数据库（二进制膨胀、备份变大）；文件用 hash 命名，DB 存真实名字 |

**依赖清单（五个）**：

```
modernc.org/sqlite                  SQLite 驱动（纯 Go）
github.com/yuin/goldmark            Markdown 渲染
github.com/microcosm-cc/bluemonday  渲染结果消毒（白名单过滤）
golang.org/x/crypto                 bcrypt
gopkg.in/yaml.v3                    只在 cmd/seed 用，不进主二进制
```

**明确不引**：Web 框架、ORM、模板引擎、session 库、前端框架、任何 CDN、代码高亮库（代码块不高亮）。

### 2.2 前端

- **无框架、无构建**。服务端渲染 HTML + 手写 CSS + 少量原生 JS。
- **零外部依赖**：不引 CDN，首屏完整，JS 只做增强。
- 字体自托管并**按站点实际用字裁剪**（见前端设计文档 §3）。

### 2.3 部署形态

- systemd 托管，监听 `127.0.0.1:8091`
- Nginx 反代，静态资源带 `immutable` 缓存
- 一个 Go 进程 + 一个 SQLite 文件 + 一个静态资源目录 + 一个附件目录 = 全部状态

## 3. 系统架构

### 3.1 拓扑

```
                     ┌───────────────────────────────┐
   访客 ──HTTP──▶    │  Nginx (:80)                  │
                     │  ├─ /assets/*  静态 immutable   │
                     │  └─ 其余 → 反代                 │
                     └──────────────┬────────────────┘
                                    │ http://127.0.0.1:8091
                     ┌──────────────▼────────────────┐
                     │  mirage-server (Go)            │
                     │  ├─ 鉴权 / 权限中间件           │
                     │  ├─ 路由 / 模板 / 静态           │
                     │  ├─ 附件上传 / 下载鉴权          │
                     │  └─ SQLite (WAL)                │
                     └──────┬──────────────┬───────────┘
                            │              │
              ┌─────────────▼──┐   ┌───────▼──────────────┐
              │ data.db         │   │ uploads/             │
              │ (SQLite 主库)   │   │ 2026/10/<hash>.pdf    │
              └─────────────────┘   └──────────────────────┘
```

### 3.2 状态都存在哪

| 状态 | 位置 | 说明 |
|---|---|---|
| 文章 / 板块 / 用户 / 会话 / 分享链接 | `data.db`（SQLite） | 唯一不可再生的，本期不备份（见 §8.4） |
| 附件原文件 | `uploads/YYYY/MM/<hash>.<ext>` | 将来启用后才有内容 |
| 字体 / CSS / JS | `static/public/`，Nginx 直出 `/assets/` | 重新构建就有 |
| HTML 模板 / SQL 迁移 | 编译进二进制（`embed.FS`） | 跟着二进制走 |

### 3.3 两级身份 + 一条旁路

这是本项目的核心设计。同一个 URL，不同身份看到的东西不一样：

| 身份 | 公开内容 | 私密内容 | 后台 | 分享 |
|---|---|---|---|---|
| **访客**（任何人，不注册） | ✅ | ❌ | ❌ | 凭链接可看指定内容 |
| **站长**（你，登录后） | ✅ | ✅ 全部 | ✅ 全功能 | ✅ 可生成 |

> **只有两级。** 没有注册、没有普通用户、没有角色管理后台。
> 但**模型是通用的**：`users` 表、`role` 字段、`perm.Can` 的 Action/Resource 抽象都留着，
> 以后想加“编辑”或“读者”角色，只是多几条数据 + 改一个 switch，不需要重构。

**外加一条旁路：分享链接**（带 token）。
凭链接访问的人即使未登录，也能看到**指定的**内容（可以是私密文章、私密板块、私密附件），
权限、有效期、访问次数由链接决定。

```
访客      ──▶  公开版：大标题 / 板块卡片 / 已发布文章
              页面顶部没有任何管理痕迹

站长登录  ──▶  公开版 + 顶栏「👤 Mirage ▾」+ 右下角悬浮工具条
              能看到未发布内容的角标（草稿 / 私密）
              文章底部多出「分享」按钮
```

### 3.4 关键设计决策

决策 1：为什么是动态后端而不是 SSG？
> 项目目标 G8（可学习）。纯静态站没有登录态、没有权限判断、没有文件上传、没有事务——学不到东西。动态后端把整条 Web 后端链路都铺开了，而 2G 内存跑一个 Go 进程完全够。

决策 2：为什么 SQLite 而不是 PostgreSQL？
> 单机部署、单一写入源、读写量极小。SQLite 的单写者限制在这里不是问题。数据量涨到需要独立数据库时再迁移，schema 是标准 SQL。

决策 3：为什么自己写会话和权限，不用现成库？
> 同样是 G8。鉴权是 Web 后端最容易“以为懂了”的部分，自己写一遍才真懂。规则又很简单，引入第三方库反而遮蔽了原理。

决策 4：附件存磁盘不存数据库
> 二进制塞进 SQLite 会让主库膨胀、备份变慢、查询变慢。文件用 **hash 命名**存磁盘（不可预测、防路径穿越），DB 只存元数据（原始文件名、大小、MIME、所属内容、权限）。

决策 5：SQLite 连接池怎么配？
> SQLite **整库级写锁，同时只有一个写者**。正确配置：
> - DSN 固定带 `_pragma=journal_mode(WAL)`、`_pragma=busy_timeout(5000)`、`_pragma=foreign_keys(1)`、`_txlock=immediate`
> - 读连接池 `SetMaxOpenConns(4)`，写连接池 `SetMaxOpenConns(1)` —— 两个独立的 `*sql.DB` 指向同一文件
> - 所有 PRAGMA 必须写在 **DSN** 里（连接级），不能写成一次 `db.Exec("PRAGMA ...")`
> - 事务要短：`BEGIN IMMEDIATE` 立刻拿写锁，事务内**不做** HTTP 调用、文件 IO、模板渲染

> 注意：已知坑（SQLite 官方与驱动文档）：
> - WAL **不解除写序列化**，只有一条写者
> - `busy_timeout` 只是把瞬时竞争变成可容忍的等待，不是并发策略
> - 备份必须用 `VACUUM INTO` 或 Online Backup API，**不能只拷 `app.db`**（已提交事务可能还在 `app.db-wal`）
> - SQLite 3.51.3 修过 WAL reset 偶发损坏竞态；驱动 ≥ v1.59.1 内置 3.53.4，不受影响

## 4. 数据模型

### 4.1 表结构

```sql
-- ① 用户（本期只有 1 条：站长。表结构留着，以后加角色不用改 schema）
CREATE TABLE users (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    username      TEXT    NOT NULL UNIQUE,
    display_name  TEXT    NOT NULL,
    email         TEXT,
    password_hash TEXT    NOT NULL,          -- bcrypt
    role          TEXT    NOT NULL DEFAULT 'owner',   -- owner（本期唯一角色）
    status        TEXT    NOT NULL DEFAULT 'active',  -- active | disabled
    created_at    INTEGER NOT NULL,
    updated_at    INTEGER NOT NULL,
    last_login_at INTEGER
);

-- ② 会话
CREATE TABLE sessions (
    id         TEXT    PRIMARY KEY,           -- 随机 32 字节 hex
    user_id    INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    created_at INTEGER NOT NULL,
    expires_at INTEGER NOT NULL,
    user_agent TEXT,
    ip         TEXT
);
CREATE INDEX idx_sessions_user    ON sessions(user_id);
CREATE INDEX idx_sessions_expires ON sessions(expires_at);

-- ③ 板块
CREATE TABLE sections (
    slug        TEXT PRIMARY KEY,
    title       TEXT    NOT NULL,
    icon        TEXT    NOT NULL DEFAULT '📁',
    summary     TEXT    NOT NULL DEFAULT '',
    color       TEXT    NOT NULL DEFAULT '#C26D7C',
    intro_md    TEXT    NOT NULL DEFAULT '',
    cover       TEXT,
    visibility  TEXT    NOT NULL DEFAULT 'public',  -- public | private
    in_nav      INTEGER NOT NULL DEFAULT 1,         -- 1 = 出现在顶栏导航
    count_label TEXT    NOT NULL DEFAULT '',        -- 卡片上的计数文案，如 "7 篇"；留空则不显示
    sort_order  INTEGER NOT NULL DEFAULT 0,
    created_at  INTEGER NOT NULL,
    updated_at  INTEGER NOT NULL
);

-- ④ 板块子页面
CREATE TABLE section_pages (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    section     TEXT    NOT NULL REFERENCES sections(slug) ON DELETE CASCADE,
    slug        TEXT    NOT NULL,
    title       TEXT    NOT NULL,
    icon        TEXT    NOT NULL DEFAULT '📄',
    summary     TEXT    NOT NULL DEFAULT '',
    body_md     TEXT    NOT NULL DEFAULT '',
    visibility  TEXT    NOT NULL DEFAULT 'public',  -- public | private
    sort_order  INTEGER NOT NULL DEFAULT 0,
    created_at  INTEGER NOT NULL,
    updated_at  INTEGER NOT NULL,
    UNIQUE(section, slug)
);

-- ⑤ 文章
CREATE TABLE posts (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    slug         TEXT    NOT NULL UNIQUE,      -- URL: /blog/<slug>/
    title        TEXT    NOT NULL,
    summary      TEXT    NOT NULL DEFAULT '',
    body_md      TEXT    NOT NULL,
    section      TEXT    NOT NULL DEFAULT 'notes',
    author_id    INTEGER REFERENCES users(id) ON DELETE SET NULL,
    tags         TEXT    NOT NULL DEFAULT '[]',   -- JSON 数组
    cover        TEXT,
    status       TEXT    NOT NULL DEFAULT 'draft',   -- draft | published
    visibility   TEXT    NOT NULL DEFAULT 'public', -- public | private
    reading_minutes INTEGER NOT NULL DEFAULT 1,  -- 迁移时按正文算好，见 §7
    published_at INTEGER,
    content_updated_at INTEGER,                  -- 原 frontmatter 的 updatedDate，可空
    created_at   INTEGER NOT NULL,
    updated_at   INTEGER NOT NULL,
    sort_order   INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX idx_posts_status  ON posts(status, published_at DESC);
CREATE INDEX idx_posts_section ON posts(section, status, published_at DESC);

-- ⑥ 附件（宿主二选一）
-- 本期【不实现上传】，只留表结构和接口。等真有东西要存再启用。
-- 宿主用 owner_key 存复合键而不是行号：sections 的主键是 slug，根本没有 id 可存。
CREATE TABLE attachments (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    owner_type   TEXT    NOT NULL,             -- post | section
    owner_key    TEXT    NOT NULL,             -- post:12 / section:notes
    filename     TEXT    NOT NULL,             -- 原始文件名（展示用）
    stored_name  TEXT    NOT NULL,             -- 磁盘上的 hash.ext
    mime         TEXT    NOT NULL DEFAULT 'application/octet-stream',
    size         INTEGER NOT NULL,
    sha256       TEXT    NOT NULL,
    visibility   TEXT    NOT NULL DEFAULT 'public',
    uploaded_by  INTEGER REFERENCES users(id) ON DELETE SET NULL,
    created_at   INTEGER NOT NULL,
    CHECK (owner_type IN ('post', 'section'))
);
CREATE INDEX idx_attach_owner ON attachments(owner_type, owner_key);

-- ⑦ 分享链接
CREATE TABLE share_links (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    token        TEXT    NOT NULL UNIQUE,       -- 32 字节随机 hex
    target_type  TEXT    NOT NULL,              -- post | section | section_page | attachment
    target_key   TEXT    NOT NULL,              -- post:12 / section:notes / section_page:studio/speeddraw / attachment:3
    password_hash TEXT,                        -- 可选：访问密码
    expires_at   INTEGER,                       -- 可选：过期时间
    max_visits   INTEGER,                       -- 可选：最大授权次数
    visit_count  INTEGER NOT NULL DEFAULT 0,
    created_by   INTEGER REFERENCES users(id) ON DELETE SET NULL,
    created_at   INTEGER NOT NULL
);
CREATE INDEX idx_share_token ON share_links(token);

-- ⑧ 站点设置（键值）
CREATE TABLE settings (
    key   TEXT PRIMARY KEY,
    value TEXT NOT NULL
);

-- ⑨ 迁移版本
CREATE TABLE schema_migrations (
    version    INTEGER PRIMARY KEY,
    applied_at INTEGER NOT NULL
);
```

## 5. HTTP 接口

### 5.0 通用约定

这几条定死，handler 和模板都按这个来，别各写各的。主题和模板以后怎么改都基于这套约定。

**时间**：JSON 里一律用 Unix 秒（整数），不用 ISO8601 字符串。要显示成「2026-10-03 星期三」在模板层格式化。

**分页**：列表接口统一 `?page=N`（从 1 开始）+ `?per_page=M`（默认 20，最大 100）。响应结构统一：

```json
{
  "items": [],
  "page": 1,
  "per_page": 20,
  "total": 42,
  "has_more": true
}
```

`total` 一并带上，模板判断时不用再算。

**错误**：JSON 接口的错误响应统一结构：

```json
{
  "error": {
    "code": "invalid_slug",
    "message": "slug 只能包含小写字母、数字和连字符"
  }
}
```

`code` 是给程序看的稳定标识，不许改；`message` 是给人看的，可以改。后台的表单接口不用 JSON，错误直接渲染回表单，带字段级提示。

**状态码**：200 / 303 / 400 / 401 / 403 / 404 / 409 / 429 / 500。创建成功用 303 跳回列表页（POST-redirect-GET）。

**URL**：页面路径一律带尾斜杠（`/blog/`），静态资源不带（`/assets/css/app.abc.css`）。`/blog/x` 自动 301 到 `/blog/x/`。

**响应头**：HTML 是 `text/html; charset=utf-8`，JSON 是 `application/json; charset=utf-8`，两者都带 `X-Content-Type-Options: nosniff`。

**缓存**：HTML 一律 `Cache-Control: no-cache`（内容随时会改）；静态资源由 Nginx 发 `immutable, max-age=31536000`。

**配色 Cookie**：`mirage_theme`（可选，值 `paper` / `sky` / `mint`）。这是**站长自己的偏好**，只影响他本人，不影响别人，也不用写库。服务端只在当前请求是登录的站长时才读它——访客带着这个 Cookie 来，服务端也当没看见。配色方案的完整规则见《前端设计文档》§1.6。

```json
{
```

**排序规则**（全站统一，别各处自己写）：

| 场景 | 规则 |
|---|---|
| 文章列表（首页/博客/板块/标签） | `published_at` 倒序；同一时间戳按 `id` 倒序兜底，保证顺序稳定 |
| 上一篇 / 下一篇 | 在同一个排序序列里取相邻两篇。**只算已发布且公开的**，私密文章不参与（否则会泄露私密文章的存在） |
| 归档 | 按 `published_at` 的年月分组，年份倒序，组内再按时间倒序 |
| 标签列表 | 按文章数倒序，数量相同按标签名排 |

**计数口径**：所有对外显示的计数（标签的文章数、归档每组的文章数）都只统计 `status='published'` 且 `visibility='public'` 的文章。站长的后台看到的数量另算。

### 5.5 分享链接访问

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET /s/{token}` | 分享页 | 依次校验：链接存在 → 未过期 → 剩余次数 → 是否需要密码 |
| `POST /s/{token}` | 提交密码 | 校验密码，通过后签发**绑定这条链接**的临时授权 Cookie |

授权 Cookie 绑单个 token（这是关键）：

- Cookie 名 `mirage_share`，值形如 `v1.<token>.<过期时间戳>.<HMAC>`，HMAC 用 `MIRAGE_SECRET` 算，签名内容是 `share:<token>:<过期时间戳>`。
- 服务端只认“签名对得上、token 也对得上”的那一条链接。过了密码的 Cookie 打不开别的分享链接。
- 不把 token 本身当成凭证放进 Cookie——那样等于“拿到 Cookie 就等于过了密码”。
- TTL 2 小时，过期后重新输密码。
- 分享页走独立路由，不渲染站点导航。拿到链接的人看到的就是你想给他看的那一份。

**次数怎么算：`max_visits` 限制的是通过密码校验的次数**（`visit_count` 每次密码校验通过 +1）。持 Cookie 期间的免密访问不计数——否则“输一次密码看十次”和“最多 3 次”自相矛盾。

**分享页能做什么**：只读。分享链接把一份内容交给指定的人看，不带任何写操作（本期没有评论，所以也不需要 `permission` 字段；将来加评论时再加一条迁移）。

> 分享链接走独立路由，不污染公开页面。拿到链接的人看到的**就是你想给他看的那一份**。

### 5.7 订阅源与索引

| 路径 | 格式 | 内容 |
|---|---|---|
| `GET /rss.xml` | RSS 2.0 | 最近 20 篇已发布公开文章 |
| `GET /sitemap.xml` | sitemap 0.9 | 全站公开页面，不含私密和草稿 |
| `GET /robots.txt` | text | `User-agent: *` + `Allow: /` + `Disallow: /admin/` + `Disallow: /s/` + `Sitemap:` 指向自己的 sitemap |
| `GET /search-index.json` | JSON | 公开已发布文章的搜索索引 |

**RSS 条目字段**：`title` / `link`（绝对 URL）/ `guid`（用文章 slug）/ `pubDate`（RFC 2822 格式）/ `description`（取 summary）/ `author`（站点作者）/ `category`（每个 tag 一条）。

**sitemap 收录范围**：

- 所有已发布且公开的文章
- 所有公开板块页和公开子页面
- 首页、`/blog/`、`/tags/`、`/archive/`、`/about/` 这些固定页
- 不包括私密文章、草稿、`/s/` 分享页、`/admin/`

**搜索索引**：

```json
[
  {
    "slug": "nginx-location-priority",
    "title": "一条 Nginx 配置，安静地废掉了我整个缓存策略",
    "summary": "location 里的 immutable 一直没生效……",
    "text": "正文纯文本，去掉了 Markdown 标记",
    "tags": ["Nginx", "缓存", "排障"]
  }
]
```

- 只含公开已发布文章
- `text` 是去掉 Markdown 标记后的全文，浏览器拿到后自己做子串匹配（标题命中权重高）
- 运行时生成，不缓存——内容随时会改
- 这个接口是「服务端渲染 + 少量原生 JS」架构下唯一需要给前端喂数据的 JSON，搜索框靠它就够了

### 5.8 后台表单字段

后台的写操作全是表单 POST（`application/x-www-form-urlencoded`），字段如下。每个表单都带隐藏的 `csrf_token`。

**文章**（`POST /admin/posts` 新建、`POST /admin/posts/{id}` 更新，同一套字段）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `title` | 文本 | 是 | ≤ 200 字符 |
| `slug` | 文本 | 是 | `^[a-z0-9]+(-[a-z0-9]+)*$`，留空则从标题生成；已被占用返回 409 |
| `summary` | 文本 | 否 | ≤ 500 字符 |
| `body_md` | 文本 | 是 | Markdown 源码 |
| `section` | 下拉 | 是 | 板块 slug，默认 `notes` |
| `tags` | 文本 | 否 | 逗号分隔，每项 ≤ 30 字符，最多 10 个，存库转 JSON 数组 |
| `cover` | 文本 | 否 | 站内图片路径，如 `/assets/img/xxx.webp` |
| `status` | 下拉 | 是 | `draft` / `published` |
| `visibility` | 下拉 | 是 | `public` / `private` |
| `published_at` | 文本 | 否 | 留空则用当前时间；格式 `YYYY-MM-DD HH:MM` |

- `reading_minutes` 不给手填，服务端按正文算好存库
- 存草稿时 `published_at` 可以留空。草稿排在所有文章之后（SQLite 里 NULL 最小，倒序排最后）
- `POST /admin/posts/{id}/publish` 是发布/撤稿的快捷入口，只改 `status`，不带其他字段
- **删除是真删**：文章连同它的子页面、附件记录一起删掉。误删没法恢复，所以后台删除按钮要二次确认

**板块**（`POST /admin/sections`，新建和更新同一套字段，用 slug 定位）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `slug` | 文本 | 是 | 正则同上；撞保留字返回 400；已存在则视为更新 |
| `title` | 文本 | 是 | ≤ 100 字符 |
| `icon` | 文本 | 否 | 一个 emoji，默认 `📁` |
| `summary` | 文本 | 否 | ≤ 200 字符，板块卡片上那一行 |
| `color` | 文本 | 否 | 十六进制颜色，默认 `#C26D7C` |
| `intro_md` | 文本 | 否 | 板块落地页的正文 |
| `cover` | 文本 | 否 | 站内图片路径 |
| `visibility` | 下拉 | 是 | `public` / `private` |
| `in_nav` | 复选 | 否 | 勾选为 1，不勾为 0，默认 1 |
| `count_label` | 文本 | 否 | ≤ 20 字符，卡片上那行计数 |
| `sort_order` | 整数 | 否 | 默认 0 |

**子页面**（`POST /admin/sections/{slug}/pages`）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `section` | 隐藏 | 是 | 板块 slug |
| `slug` | 文本 | 是 | 同一板块内唯一，正则同上 |
| `title` | 文本 | 是 | ≤ 100 字符 |
| `icon` | 文本 | 否 | 默认 `📄` |
| `summary` | 文本 | 否 | ≤ 200 字符 |
| `body_md` | 文本 | 是 | Markdown 源码 |
| `visibility` | 下拉 | 是 | `public` / `private` |
| `sort_order` | 整数 | 否 | 默认 0 |

**站点设置**（`POST /admin/settings`）：

| 字段 | 说明 |
|---|---|
| `site_title` `site_subtitle` `site_description` `site_author` `site_since` `home_status` | 文本，逐项提交，值为空则清空该项 |
| `site_url` | 站点对外基础地址，如 `http://www.miragewzy.online`，不带尾斜杠。换域名时改这里 |
| `home_tags` | 逗号分隔，存库转 JSON 数组，最多 10 个，每项 ≤ 20 字符 |
| `theme_today` | 下拉，`auto` / `paper` / `sky` / `mint`。`auto` = 按日期自动轮换；钉死某版则全站都用它（对所有访客生效） |
| `current_password` + `new_password` | 改密码用，两栏都填才生效；`new_password` 至少 8 位；改完吊销该用户所有会话 |

- 设置项没有「新增自定义键」这个能力，`settings` 表就这 9 个键加上密码

**分享链接**（`POST /admin/share`）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `target_type` | 下拉 | 是 | `post` / `section` / `section_page` |
| `target_key` | 文本 | 是 | 复合键，如 `post:12` / `section:notes`；后台从下拉里选，前端拼好 |
| `password` | 文本 | 否 | 留空表示不要密码；非空则存 bcrypt 哈希 |
| `expires_at` | 文本 | 否 | 留空表示永久；格式 `YYYY-MM-DD HH:MM` |
| `max_visits` | 整数 | 否 | 留空表示不限；≤ 0 视为不限 |

- 创建后一次性把完整 URL 显示给站长（`/s/<token>`），关掉页面就看不到了，列表里还能复制
- `POST /admin/share/{id}/revoke` 作废：**不删记录**，置 `revoked` 为真，作废后链接立刻失效

**后台首页**（`GET /admin/`）的概览数据：

```json
{
  "counts": { "posts": 12, "drafts": 3, "shares": 4 },
  "recent_posts": []
}
```

- `posts` 是全部文章数，`drafts` 是草稿数，`shares` 是有效分享链接数
- `recent_posts` 取最近改的 5 篇

## 6. 认证与权限设计

### 6.1 密码与会话

```bash
MIRAGE_OWNER_PASSWORD=<初始密码>   # 只在 cmd/seed 首次建 owner 时用一次
MIRAGE_SESSION_TTL=168h            # 会话有效期，默认 7 天
MIRAGE_SECRET=<64位随机 hex>        # 签名密钥，缺失则拒绝启动
```

`MIRAGE_SECRET` 部署时生成一次，写进 `/etc/mirage/env`（权限 0640 root:mirage），之后不再变：

```bash
openssl rand -hex 32
```

- 密码用 bcrypt（cost ≥ 12） 存 `users.password_hash`
- 登录成功后：生成 **32 字节随机** `session.id`（`crypto/rand`），写 `sessions` 表
- Cookie 只存 **session id，服务端查表决定是否有效 → 可随时踢人下线**（比纯签名 Cookie 强）
- Cookie 属性：`HttpOnly`、`SameSite=Lax`、`Secure`（有 HTTPS 时）、`Path=/`
- `sessions.expires_at` 过期自动清理（每小时一次定时任务，登录时也顺手清一次）
- 登录成功时**轮换 session id**，防会话固定

> 为什么不在 Cookie 里直接放用户信息？那样改密码/禁用账号都踢不掉人。放 session id + 查表，多一次查询，换来“随时可吊销”。

### 6.2 权限模型

**资源 × 动作**的二维判定。核心是一个纯函数：

```go
// internal/perm/perm.go
type Action string
const (
    ActionRead   Action = "read"
    ActionWrite  Action = "write"
    ActionDelete Action = "delete"
    ActionAdmin  Action = "admin"
)

type Resource struct {
    Type       string   // post | section | section_page | attachment | comment
    Visibility string   // public | private
    Status     string   // draft | published
    OwnerID    int64    // 创建者
}

func Can(user *model.User, a Action, r Resource) bool
```

判定顺序：

1. user == nil（访客） → 只允许 `read`，且资源必须 `visibility == 'public'`；`post` 还要求 `status == 'published'`。其余全部拒绝。
2. user.Status == 'disabled' → 全部拒绝。账号被停用就不是账号了，哪怕 Cookie 还有效。
3. user.Role == 'owner'（站长） → 一律允许。
4. 其余情况（未来的普通用户）→ 暂时全拒。

> `visibility` 两档：
> - `public` — 所有人可见
> - `private` — 只有站长可见（**要分享出去就生成分享链接**）
>
> `status` 两档：`draft` / `published`（`draft` 只有站长可见）。
> `sections` / `section_pages` 没有草稿概念，它们的 `Status` 恒为 `published`，由 `perm.ResOf` 填好。
>
> **以后要加普通用户**：在 `visibility` 里加一档 `members`，
> 在第 1 条和第 3 条之间插一条判断（登录用户可读 members），
> `users` 表加几条记录即可。**架构不用动。**

这个函数是纯函数、无副作用、只依赖入参 → 好测、好推理。这是本项目最值得学的模块。

### 6.3 视图差异怎么实现

关键点：权限判定只在两个地方发生，其余地方一律复用。

1. **数据层**：`store` 的查询方法接收一个 `Visibility` 过滤条件，由 `web` 层根据当前用户算好后传进去。
2. **模板层**：模板**不写权限判断**，只根据已经算好的 View Model 字段决定显示什么。

```go
// web/handler.go —— 只算一次，全部走 perm.Can
res := perm.ResOf(p)
vm := postView{
    Post:      p,
    CanEdit:   perm.Can(u, perm.ActionWrite, res),
    CanShare:  perm.Can(u, perm.ActionWrite, res),
    ShowTools: perm.Can(u, perm.ActionAdmin, res),
}
```

模板里就写 `{{ if .ShowTools }}<div class="toolbar">…</div>{{ end }}` —— **不碰权限逻辑**。

> 这是新手最容易写错的地方：权限判断散落在模板里 → 逻辑重复 → 迟早漏一个地方 → 越权。全部收口到 `perm.Can` + View Model。
> 反过来也成立：handler 里不许出现 `u.Role == "owner"` 这种写法，哪怕现在只有一个角色——那等于开了第二个权限判断入口，早晚会有人在这里加分支。

### 6.4 CSRF

**登录用户（管理操作）**：

- 所有 `POST` 表单带隐藏字段 `csrf_token` 和 `csrf_at`
- token = `HMAC-SHA256(SECRET, session_id + "|" + form_action + "|" + csrf_at)`
- 服务端重算并比对，不匹配返回 403
- `csrf_at` 是签发时的 Unix 秒，超过 4 小时视为过期
- Cookie `SameSite=Lax` 兜底，不作为唯一防线

**匿名用户（分享密码）**：

- 表单带隐藏字段 `csrf_token` = `HMAC-SHA256(SECRET, "anon:" + 匿名 cookie 值 + "|" + form_action)`
- 服务端同时校验：匿名 cookie 存在、cookie 值与签名都对得上
- 说清楚边界：这挡的是“别的站直接裸 POST 过来”和“没带 cookie 的脚本提交”，**挡不住同源伪造**——匿名用户本来也没有身份可盗。真正的防刷靠 IP 限流（分享密码试错限制见 §6.5）。

### 6.5 分享链接的密码与次数

- `token`：`crypto/rand` 32 字节 hex
- 访问密码：bcrypt 哈希存 `password_hash`
- 有效期：`expires_at` Unix 秒，NULL = 永久
- 次数：`max_visits` 限制**密码校验通过**的次数，`visit_count` 每次 +1，超了拒绝
- 输对密码后签发**绑定这条链接**的临时授权 Cookie（TTL 2 小时），避免每次都输
- 授权 Cookie 的格式和校验见 §5.5：一条链接一个 Cookie，打不开别的链接
- 密码错误要限流：同一 IP 对同一 token 每小时最多试 10 次（bcrypt 本身就慢，但别拿它当防护）

### 7.2 文章从哪来

两种方式，都支持：

**后台写。** 站长登录后在 `/admin/posts` 新建，正文是 Markdown 源码。这一条是主路径，站点本来就是拿来即时改内容的。

**本地写文件再导入。** 适合一次写好几篇长文：在 `content/blog/` 放 Markdown 文件，跑一次导入。


导入时按这个映射写库：

| 字段 | 来源 |
|---|---|

### 7.3 阅读时长怎么算

```
分钟数 = 中文字数 / 350 + 英文词数 / 220 + 代码块行数 × 1.5 / 60
```

取整，最少 1 分钟。算完存进 `posts.reading_minutes`，前台直接读，不在请求时现算。

### 8.2 新服务

```bash
# 服务账号（一次性：系统用户，不给登录 shell）
sudo useradd --system --no-create-home --shell /usr/sbin/nologin mirage

# 二进制
/usr/local/bin/mirage-server          # ~10-15 MB

/var/lib/mirage/data.db               # SQLite
/var/lib/mirage/public/assets/        # 静态资源（发布产物）
/var/lib/mirage/uploads/              # 附件（本期不用，先建好目录占位）

/etc/mirage/env                        # 权限 0640 root:mirage

```

`/etc/mirage/env` 的内容：

```bash
MIRAGE_SECRET=<openssl rand -hex 32 的结果>
MIRAGE_SESSION_TTL=168h
```

`MIRAGE_OWNER_PASSWORD` **不放进 env**——它只在首次迁移时用一次，用完即弃。

systemd unit 要点：

```ini
[Unit]
After=network-online.target
[Service]
User=mirage
Group=mirage
```

`User=mirage` 指的那个系统用户**必须先建**（上面第一条 `useradd`），否则 systemd 直接起不来。

### 8.3 Nginx 改动

只改 `sites-available/mirage`（当前是占位版），**不动** `nginx.conf` 和其他文件。

```nginx
server {
    listen 80;
    server_name www.miragewzy.online miragewzy.online;

    client_max_body_size 32m;          # 附件上传上限（将来启用附件时才需要）

    # 静态资源直出。发布产物统一放在 static/public/ 下，发布时整目录传上去。
    # alias 必须带结尾斜杠，否则路径拼接会少一段。
    location ^~ /assets/ {
        alias /var/lib/mirage/public/assets/;
        expires 1y;
        add_header Cache-Control "public, immutable";
        include snippets/site-security.conf;
    }

    location / {
        proxy_pass http://127.0.0.1:8091;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;        # 取真实 IP 只认这个
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        client_max_body_size 32m;
    }
}
```

> 静态资源只有一个前缀 `/assets/`。字体、CSS、JS 发布时都生成到 `static/public/assets/` 下面，
> 文件名带内容哈希（`app.3f9a1c.css`、`lxgw-wenkai-subset.7b2e4d.woff2`），所以可以放心 `immutable`。
> 不要再开 `/_fonts/`、`/css/` 这类第二前缀——多一套就多一处要同步的地方。

> 注意：**已踩过的坑**（别重犯）：
> 1. 哈希资源必须 `location ^~ /assets/`，不能用普通 `location`——正则 location 优先级更高会抢走，导致 `immutable` 静默失效
> 2. `add_header` 在子层级会**覆盖**父层级**全部** `add_header`。要多个安全头必须抽 snippet 然后每处 `include`
> 3. 80 端口**不能 301 跳 HTTPS**——CDN 回源跟着跳会成环
> 4. 改任何 nginx 配置前先 `cp -a` 备份，改完必须 `nginx -t` 再 `reload`
> 5. 上传大文件时 `client_max_body_size` 要在 `server` 和 `location` **两处**都写，否则代理层会先拒

### 8.4 备份（本期不做）

**不做定时备份，这是有意接受的风险。** git 里是代码和文档，没有数据库——`.db` 是 gitignore 的，文章写完只在 `data.db` 里，磁盘坏或误删库就没了。唯一例外是文章在本地写成 Markdown 文件再导入的，那 git 里天然有副本。

将来想补的时候用 `VACUUM INTO`（**不能裸拷**，WAL 模式下会拷到缺数据的库）：

```bash
sqlite3 /var/lib/mirage/data.db "VACUUM INTO '/var/backups/mirage/data-$(date +%F).db'"
sqlite3 /var/backups/mirage/data-$(date +%F).db "PRAGMA integrity_check;"
```

恢复时记得删掉残留的 `data.db-wal` 和 `data.db-shm`。要防磁盘坏，还得多一份异地备份（推 GitHub 私有库 / 传自己电脑 / 对象存储），这一层本期也不做。

| **HTTPS 未解决** | 443 被 NPM 占着且证书是废的，域名 HTTPS 访问直接握手失败 | 暂不申请，先用 http://。现在没接 CDN，certbot HTTP-01 值得再试（见 D7）。代价：分享链接密码明文过网 |
| **内存紧张** | 1.9G 已跑 6 个服务 | Go 进程 < 40MB；2G swap 已在；附件走磁盘不进内存（将来启用时流式写） |
| **SQLite 单写者** | 并发写会 `database is locked` | 写连接池 1 + WAL + `busy_timeout` + `BEGIN IMMEDIATE` + 短事务 |
| **上传大文件打爆内存**（将来） | `ParseMultipartForm` 会把整个文件读进内存 | 设 `MaxBytesReader`；**用 `FormFile` 的流式接口逐块写盘**，不要 `ReadAll` |
| **附件撑爆磁盘**（将来） | 大文件堆积 | 上传上限 32MB + 总量配额 10GB + 后台可查用量 |
| **路径穿越**（将来） | 上传文件名可控 | 磁盘名用 **sha256 hash**，绝不用原始文件名；下载时从 DB 取元数据，不从 URL 拼路径 |
| **越权访问附件**（将来） | 知道 URL 就能下私密附件 | 每次下载都查宿主内容的权限 |
| **字体体积** | 霞鹜文楷完整 TTF 24MB | 发布时按实际用字裁剪（24MB → 64KB），产物是发布期生成物 |
| **新字缺字形** | 裁剪后的字体没有新文章用到的字 | 缺字会退回系统字体渲染（**不会变成方框**），只是观感不统一；下次发布重裁即可 |
| **数据库没备份**（有意接受） | 磁盘坏或误删库 → 写过的文章全没了，git 救不回（`.db` 被 gitignore） | 本期不做定时备份；文章在本地写 Markdown 的话 git 里有副本 |
| **GitHub 不通** | 服务器拉 GitHub 经常 TLS 重置 | 服务器不拉代码。代码托管 GitHub（`mirage-xy/mirage-blog`），发布是本地 `make build` + `scp`，本机走 SSH over 443 |
| **CDN 回源成环**（将来若接 CDN） | 80 端口跳 HTTPS 会成环 | 现在没接 CDN，不存在；规则先留着：80 端口直接吐内容，不跳转 |

## 11. 项目结构

```
mirage/
├── cmd/
│   ├── mirage-server/main.go     主服务
│   └── seed/main.go              一次性初始化脚本（建表 + 初始数据 + 建 owner）
├── internal/
│   ├── config/                   配置加载（env）
│   ├── model/                    领域模型（纯结构体）
│   ├── store/                    数据访问（唯一写 SQL 的地方）
│   ├── perm/                     权限判定（纯函数）
│   ├── auth/                     密码哈希、会话、CSRF
│   ├── share/                    分享链接的生成与校验
│   ├── attachment/               上传落盘、下载鉴权（本期只留接口）
│   ├── render/                   Markdown 渲染 + 消毒 + 目录提取
│   ├── assets/                   资源名解析（开发拼路径 / 生产查 manifest.json）
│   └── web/                      HTTP 层：路由、中间件、handler
├── templates/                    Go html/template（embed 进二进制）
├── static/
│   ├── src/                      CSS/JS 源文件
│   └── public/                   发布产物（字体、哈希后的 CSS/JS），不入库
├── migrations/                   SQL 迁移（embed 进二进制）
├── tools/subset-font.py          字体裁剪
├── scripts/{build,deploy}.sh
├── content/blog/                 本地写的文章（可选，后台写就不需要这个目录）
├── assets/fonts/                 字体源文件
└── docs/                         五份文档
```

**分层规则（不能跨层）**：

```
web ──→ store ──→ model
 │        │  ↑
 │        └──┘  依赖 perm.VisibilityFilter
 │
 └──→ perm / auth / share / render
```

三条容易搞混的，说清楚：

- `perm` 是**纯函数，不碰 SQL、不碰 HTTP。`auth` 和 `share` 要查库（会话表、分享链接表），所以它们不是“纯逻辑”，只是不碰 HTTP**。把三个包并列成“纯逻辑”是错的。
- `store` 可以 import `perm`（用它提供的 `VisibilityFilter`），`perm` 绝不 import `store`。
- `web` 层不允许直接写 SQL；SQL 只出现在 `store` 和 `migrations/`。

硬性约束：

- `web` 层**不允许**直接写 SQL
- `store` 层**不允许**引用 `net/http`
- `model` 层**不允许** import 任何项目内其他包
- `perm` 层**不允许**碰数据库和 HTTP（保证是纯函数）
