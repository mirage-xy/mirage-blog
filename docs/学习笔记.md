## M1 · 骨架（2026-11-23 完成；2026-10-31 那版已撤销）

> **正式版已落地**：`cmd/mirage-server/main.go` + `internal/config` + `internal/web`，6 个文件、645 行。
> 下面四段前半记的是 2026-10-31 试写那版的通用机制（跟代码在不在没关系），标 **补记** 的是正式实现这一轮新增的。

### 学到的

- Go 1.22+ 的 `ServeMux` 直接支持方法路由：`mux.HandleFunc("GET /healthz", h)`，方法写在模式里，路径参数用 `r.PathValue` 取，不用自己解析 URL
- `signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)` 一行搞定信号监听：ctx 被取消就是收到 Ctrl+C 或 SIGTERM
- `http.Server.Shutdown(ctx)` 是优雅退出的正解：等在途请求做完，最多等一个超时，超了就强关
- listener 提前创建的好处：端口被占在 `Serve` 之前就报错了，不用等第一个请求进来才发现
- 优雅退出要能测，生命周期就不能写在 `main()` 里。挪进 `web.Server.Serve(ctx, ln)` 之后，测试可以自己拿一个随机端口的 listener，退出路径才真的被验证到
- 常驻内存和提交内存是两个指标：Windows 上 WorkingSet 8.2 MB、Private 44 MB。`ps RSS` 对应的是常驻那个，别拿 Private 当 RSS
- slog 的结构化日志：`slog.Info("http", "method", ..., "status", ...)`，key 和 value 成对写，能被 journald 和日志检索系统直接吃

**补记（正式实现）**

- 三级优先级的实现技巧：`fs.StringVar(&cfg.Addr, "addr", cfg.Addr, ...)` —— flag 的默认值取的是「环境变量已经生效之后」的那个值，所以不传 flag 就自然保留了环境变量的结果，不用写三段分支
- `flag.ContinueOnError` + `fs.SetOutput(io.Discard)` + 自己写 usage：`-h` 不会走 flag 包的默认输出，`main` 里用 `errors.Is(err, flag.ErrHelp)` 就能把「用户主动求助」（退出码 0）和「参数写错」（退出码 2）分开
- 配置可测的前提是**把取环境变量的函数当参数传进去**：`config.Load(args, getenv)`，测试换成自己的 map；12 个用例里 7 个在 config 包
- 访问日志想记状态码和字节数，必须在中间件里包一层 `ResponseWriter`（`statusRecorder`），并且补上 `Unwrap()`，否则 `http.ResponseController` 拿不到底层 writer

### 踩的坑

- 第一版 middleware.go 顺手 import 了 `log/slog`，其实用不上。编译器直接报 `imported and not used`——写完别急着跑，先 `gofmt -l .` 和 `go vet ./...` 过一遍
- 量内存的时候把 Private 当成了 RSS，一看 45 MB 以为超了 40 MB 的预算，其实是两个不同的数。Windows 会回收空闲页，所以刚启动那会儿 WorkingSet 高、空跑一会儿就降下来
- 一开始把服务生命周期写死在 `main()` 里，测试没法写。挪进 `web` 包之后，测试能自己起 listener、用随机端口，还能断言「取消之后端口真的没人听了」

**补记（收尾那天踩的）**

- `gofmt -s -w .` 报 `open internal\web\server.go.5848408371458965553: Access is denied`。文件名后面那串随机数字是线索：`gofmt -w` 不原地改文件，而是**在同目录建临时文件、写完再改名覆盖**，所以「能读能执行但建不了文件」的目录，第一步就死，报的不是「覆盖失败」而是「打开临时文件失败」
- 同一个工作区里根目录能写、子目录全被拒：查下来是 Windows 的**完整性级别**在挡。根目录带 `Low Mandatory Level` 标签，搬家过来的 `docs/`、`cmd/`、`internal/` 没带，Low 级别进程按「不准向上写」被挡住。沙箱里**新建**的目录会自动继承标签，所以只有旧目录中招——这也是判断依据：新建一个目录就能写，说明标签继承链没坏，是旧目录缺标签
- `go vet` / `go test` 即使项目目录可写也可能失败：它们要读写工作区外的 `GOCACHE`（`%LOCALAPPDATA%\go-build`），报的是 `pattern ./...: ... Access is denied`

### 怎么修的

- 生命周期挪进 `web` 包，`main` 只负责三件事：读配置、装信号、启动
- 内存按 `ps RSS` 口径量，验收标准定成「常驻 < 40 MB」
- 固定成每次写完跑三件事：`gofmt -l .`（应该没输出）、`go vet ./...`、`go test ./...`

**补记**

- 格式化仍是 `gofmt -s -w .`，核对顺序固定成：`gofmt -s -l .`（应无输出）→ `go vet ./...` → `go test ./...`
- 权限问题没有从根上改（规矩是 agent 不动文件权限），改用本会话的完全权限一次性执行，**遗留未修**：下次普通沙箱里写项目子目录、跑 vet/test 还会撞同一堵墙。判断方法记在下面「值得记住的机制」里

### 下一步想试

- 想看看两个连接池是不是真的把写串行了：并发跑 100 个写事务，看会不会有 `database is locked`
- 想搞清楚 `PRAGMA journal_mode=WAL` 到底在哪一步生效——写进 DSN 和写成一次 `db.Exec` 差在哪
- 迁移器打算用 `embed.FS` 把 `migrations/` 打进二进制，想试试 `//go:embed` 只能嵌当前包目录及其子目录这个限制

**补记**

- 想验证一下：把那几个目录的完整性标签补上之后，`gofmt -w` 和 `go test` 能不能在普通沙箱里直接跑通，不再需要提权
- M2 想亲手验证三件事：`//go:embed migrations/*.sql` 单开一个包能不能嵌到、DDL 放在事务里失败会不会真的整体回滚、写池 `SetMaxOpenConns(1)` 之后并发写还会不会有 `database is locked`

## M2 · 数据层（2026-10-31 试写过一版，代码已撤销）

> 同上，代码已撤销，状态重置。这里记的也是通用机制。

### 学到的

- **迁移不是搬数据，是管表结构的版本**。表结构会一直变（加字段、加索引），每一次改结构都是一次迁移。写进 `migrations/NNN_xxx.sql`，数据库里用 `schema_migrations` 记着跑到第几号了
- `//go:embed` 只能嵌入**当前包目录及其子目录**下的文件。所以迁移文件在仓库根，就得单独建一个包把 embed 指令放进去，写在 `cmd/` 里是嵌不到的
- **所有 PRAGMA 必须写进 DSN**。写成 `db.Exec("PRAGMA ...")` 只对当时借出的那一条连接生效，连接池里后来开的连接全都没开——外键会随机失效
- 请求 WAL ≠ VFS 真的接受了。所以开库之后要 `PRAGMA journal_mode` 查一遍，不是 "wal" 就直接报错
- 两条连接池指向同一个文件：读池 4 个连接、写池 1 个连接。SQLite 整库级写锁，写池只有 1 个连接，写就天然串行了，不用靠事务排队
- `_txlock=immediate` 让事务一开就拿写锁，而不是等到第一次写才抢
- SQLite 的 DDL 是**事务性**的：迁移放在事务里执行，失败会整体回滚，不会留下半截 schema
- 权限过滤不该用 `1 = 1` 表示「不过滤」——那会让 SQLite 走全表扫描。返回空串表示不过滤，由 store 决定要不要拼 WHERE

### 踩的坑

- 第一次编译报三个错：返回类型写错了（map 写成了 []int）；一个 `nullInt64` helper 名字起得太泛，它收的是 `*time.Time`，但另一个地方要传 `*int64`。名字不说清楚，编译器报错才看出来
- `gofmt` 把一组变量的对齐改了，不跑 `gofmt -l .` 就发现不了
- 写测试时差点用 `:memory:`。每个连接拿到的是独立的库，会随机报 "no such table"——用临时文件才对

### 怎么修的

- helper 拆成 `nullTime(*time.Time)` 和 `nullInt(*int64)` 两个，名字说清楚收什么
- 每次写完固定跑 `gofmt -s -w .` + `go vet ./...` + `go test ./...` 三连
- 测试全部用临时目录下的文件库

## 备忘：值得记住的机制

<!-- 那些“查文档要五分钟、但一旦理解就再也不会错”的东西 -->

- **SQLite 只有一条写者**：WAL 让读不阻塞写，但**写还是串行的**。写连接池 `SetMaxOpenConns(1)`。
- **`PRAGMA` 必须写进 DSN**：`db.Exec("PRAGMA ...")` 只作用于当时借出的那一条连接，池里后来开的连接没生效。
- **`//go:embed` 只能嵌当前包目录及其子目录**：文件在仓库根，就得为它单开一个包。
- **Nginx `location` 优先级**：精确匹配 > `^~` 前缀 > 正则 > 普通前缀 > 兜底。哈希资源必须用 `^~`，否则正则会抢走。
- **Nginx `add_header` 会覆盖**：子层级的 `add_header` 一旦出现，父层级的**全部** `add_header` 都失效。多头要抽 snippet。
- **`html/template` 自动转义**：在模板里做的任何字符串拼接都会先被转义。想输出原始 HTML 只能用 `template.HTML`，而那意味着**你要自己负责消毒**。
- **`ServeMux` 的 `{x}` 只匹配一段**，`{x...}` 才匹配多段。路由注册顺序不影响匹配（按具体度），但可读性上还是把通配放最后。
- **字体缺字不会变方框**：裁剪后的字体没有某个字形时，浏览器按 `font-family` 链回退到系统字体。中文系统字体一定有，所以最多是“那两个字不是霞鹜文楷”。
- **静态资源只走一个前缀**：`/assets/`。前缀一多，缓存策略和要同步的地方就多一处。
- **分享链接的授权 Cookie 绑定单个 token**：授权凭证不能是“这个站的一把总钥匙”。
- **Windows 完整性级别会静默挡住写入**：Low 级别进程写不进 Medium 级别的对象，报的只是普通的「访问被拒绝」，没有任何提示是级别问题。`icacls <目录>` 输出里有没有 `Mandatory Label\Low Mandatory Level:(OI)(CI)(NW)` 这一行，就是能不能写的依据；目录树搬家之后这个标签容易丢，**新建的对象才会自动继承**。
