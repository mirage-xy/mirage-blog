## 0. 设计理念

一句话：舒服、清新。

用户明确否定了两种方向：早期“朱印/印章”的古板感，和高饱和糖果色的甜腻感。现在的方向是：

> 低饱和 · 大留白 · 纸感 · 柔和圆角 · 通透

“清新”具体指四件事：

- 底色浅而透——冷调米白，不是纯白，也不是灰扑扑的纸色
- 强调色**只有一个**，而且是暖色——在一片冷调里跳出来，不多不少
- 圆角大、几乎没有阴影，靠留白和一条细线分区
- 不用重色块、不用渐变铺底、不用发光

四条判断标准，任何设计决策都拿它们过一遍：

1. 能读下去——长时间读技术文章不累。行高 ≥ 1.9，正文 17px，字间距略放。
2. 不抢注意力——界面安静，内容是唯一的主角。不用发光、不用霓虹、不用切角。
3. 有温度——配色只用一套，不凭空发明。字号、间距带一点手作感。
4. 所有人一样——不做“登录后换一套皮”。暗色模式是全站一致的、可持久化的偏好设置，不是权限。

**参考来源**：Astro 官方主题库（[astro.build/themes](https://astro.build/themes/)）里那些清爽的博客模板——看它们的留白比例、单一强调色、发丝描边、卡片圆角。**只抄气质不抄实现**：那些模板都是 Astro + Tailwind 写的，本项目手写 CSS，不引任何前端框架（见《决策记录》D18）。

## 1. 色彩系统

### 1.1 色彩来源

这套配色最早是从一张插画里采样出来的，插画不做了，配色留下来当起点：低饱和的冷灰蓝底，配一个暖调强调色，安静但不闷。

| 角色 | 色值 | 用途 |
|---|---|---|
| 主强调色 | `#C26D7C` | 强调文字、链接、图标底、hover 态、进度条 |
| 正文墨色 | `#3A3336` | 正文、标题 |
| 次级色 | `#39618C` | 冷色系板块色、代码块标题 |
| 暗色底色 | `#3A4B4E` | 暗色模式的底色系 |

原则：整站只用这一套色，页面之间不换皮。以后真有了插画或者照片，再回头看要不要按图重新调一遍，那时改一次令牌就行。

**这一层是主题定稿时唯一要动的地方**：换主题 = 改 `tokens.css` 里的这几个值 + 圆角阴影那几行，别的都不用碰。

### 1.2 亮色模式（默认）

```css
:root {
  /* 底 */
  --bg:            #F5F6F9;   /* 冷调米白，带一点点灰蓝 */
  --bg-warm:       #FAF7F2;   /* 备用暖底，个别页面用 */
  --bg-card:       #FFFFFF;
  --bg-subtle:     #F1F3F6;   /* 标签、输入框底 */
  --bg-banner:     #DFE4EA;   /* 头图占位底 */

  /* 字 */
  --ink:           #3A3336;   /* 正文/标题 */
  --ink-2:         #6B6265;   /* 次级文字、摘要 */
  --ink-3:         #9E9699;   /* 元信息、时间、占位符 */
  --ink-invert:    #FFFFFF;

  /* 线 */
  --line:          #E6E3E6;   /* 常规描边 */
  --line-strong:   #D4CFD4;   /* 强调描边 */

  /* 强调 */
  --accent:        #C26D7C;
  --accent-soft:   rgba(194, 109, 124, .10);  /* 淡染底 */
  --accent-softer: rgba(194, 109, 124, .06);
  --accent-strong: #A85463;   /* hover / 按下 */

  /* 状态 */
  --ok:            #4E8C7D;
  --warn:          #C89A4A;
  --danger:        #B8524E;
}
```

### 1.3 暗色模式

暗色模式不是把亮色模式反相，而是重新给一套（取自同一套色的暗部）：

```css
[data-mode="dark"] {
  --bg:            #16181C;
  --bg-card:       #1D2025;
  --bg-subtle:     #23272D;
  --bg-banner:     #2A2F36;

  --ink:           #E8E4E6;
  --ink-2:         #B3ABAE;
  --ink-3:         #837B7E;

  --line:          #2C3138;
  --line-strong:   #3A4048;

  --accent:        #E08E9C;   /* 亮色下要提亮，否则在深底上不够亮 */
  --accent-soft:   rgba(224, 142, 156, .14);
  --accent-strong: #F0A8B4;

  --ok:            #6FB3A0;
  --warn:          #D9B268;
  --danger:        #D4706B;
}
```

> 强调色在暗色模式下**必须提亮**（`#C26D7C` → `#E08E9C`），否则在深底上对比度不足。深色模式不是“取反”，是重新配。

> **注意属性名**：明暗用 `data-mode`（`light` / `dark`），配色方案用 `data-theme`（`paper` / `sky` / `mint`）。两个轴各管各的，别混。详见 §1.6。

### 1.4 板块色板

每个板块一个色，全部低饱和。色值存在 `sections.color` 里，后台加板块时自己挑一个：

| slug | 板块 | 色值 | RGB（供 `rgba()` 用） |
|---|---|---|---|
| `notes` | 手记 | `#C26D7C` | 194,109,124 |
| `about` | 关于 | `#6E7FA3` | 110,127,163 |
| `guestbook` | 留言 | `#A9707A` | 169,112,122 |

使用规则：

- 板块色只出现在：图标淡染底（`rgba(var(--rgb), .13)`）、左侧色条（3px）、子页标签文字与淡底、hover 时的“去看看”文字
- 绝不用板块色做大面积填充，卡片永远白底
- 板块色不用于正文，只用于“这里指向前往 xxx 板块”这种导航性提示

### 1.5 圆角与阴影

```css
--r-sm: 10px;    /* 标签、小图标 */
--r:    20px;    /* 卡片（主） */
--r-lg: 30px;    /* 大图框、头图 */
--r-pill: 999px; /* 药丸标签 */

--shadow-card:  0 8px 26px -20px rgba(57, 97, 140, .16);
--shadow-hover: 0 18px 40px -22px rgba(57, 97, 140, .22);
--shadow-banner: 0 26px 70px -34px rgba(57, 97, 140, .28);
```

**阴影一律用冷色**（`rgba(57,97,140,...)`），不用黑色。黑色阴影在冷调底上会显脏。

### 1.6 配色方案：每日一换

三套配色方案轮着来，一天一版。三版的页面结构完全一样，**差的只是令牌**——所以换版就是换一组 CSS 变量，HTML 一行都不用改。

| 方案 | 底色 | 强调色 | 标题字 | 圆角 | 气质 |
|---|---|---|---|---|---|
| **纸间** `paper` | `#FAF8F4` 暖纸白 | `#C26D7C` 玫瑰灰 | 霞鹜文楷（楷体回退） | 16px | 安静、有手作温度 |
| **青空** `sky` | `#F6F8FB` 冷调浅灰蓝 | `#3B6FE0` 清蓝 | 粗黑体 | 10px | 工程师式的利落 |
| **薄荷** `mint` | `#F5FAF7` 微绿白 | `#2F8F6B` 薄荷绿 | 粗黑体 | 18px | 柔和、鲜亮 |

每套方案在 `tokens.css` 里是一组 `[data-theme="xxx"]` 变量，覆盖 §1.2 的默认值。**其余令牌（间距、字号、阴影、字体栈）三版共用**，只有颜色、圆角、标题字体跟着变。

**两个轴分开**：

| 轴 | 属性 | 取值 | 谁定 |
|---|---|---|---|
| 明暗 | `data-mode` | `light` / `dark` | 访客自己（☾ 按钮，存 localStorage） |
| 配色方案 | `data-theme` | `paper` / `sky` / `mint` | 站长（每日自动 + 手动覆盖） |

**每日一换**：按日期算，三版循环（`dayIndex % 3`）。跨时区按**服务器本地日期**算，站点时区固定 UTC+8。

**服务端定方案（关键）**：服务端算出今天该用哪版，**直接渲染进 HTML**：

```html
<html data-theme="mint" data-mode="light">
```

这样首屏就是对的，不闪白，而且访客禁用 JS 也是对的配色。JS 只负责浮层交互和明暗切换。

**优先级**：

```
个人偏好（站长自己的 Cookie，只影响他）  ← 最高
站点设置 settings.theme_today（对所有访客生效）
按日期自动                          ← 兜底
```

`settings.theme_today` 取值 `auto` / `paper` / `sky` / `mint`，`auto` 就是按日期走。站长在后台设置里可以钉死某版（比如整个月都用薄荷）。

**只有站长能手动切**：

- 登录后的顶栏右侧多一个**小色点**（直径 22px，就是当前强调色），点开是浮层：跟随日期 / 纸间 / 青空 / 薄荷
- 选了存 Cookie `mirage_theme`，**只影响他自己**，不影响别人，也不用写库
- **访客没有任何配色入口**。访客只有明暗切换（☾），那不影响配色方案
- URL 参数 `?theme=paper` **只对登录的站长生效**（服务端判断），用来快速预览某版
- 浮层入口由服务端按身份决定是否渲染——访客的 HTML 里连这个按钮都没有

**过渡**：切换时颜色 `.9s ease` 过渡。`prefers-reduced-motion: reduce` 时禁用过渡，直接切。

**暗色只有一套**：三套方案只影响亮色。暗色模式沿用 §1.3 那套中性暗色，不随方案变——否则工作量翻三倍，而暗色是少数场景。暗色下的强调色取当前方案的提亮版（纸间 `#E08E9C`、青空 `#7FA6F5`、薄荷 `#63C4A0`），用一个变量注入。

## 2. 排版与间距

### 2.1 字体

**正文用仿宋，英文用 Times New Roman。三版配色共用这一套。**

```css
--font-body: "Times New Roman", "FangSong", "仿宋", "STFangsong", "Songti SC", "Noto Serif CJK SC", serif;
--font-mono: "LXGW WenKai Mono", ui-monospace, SFMono-Regular, Consolas, monospace;
```

**字体栈的顺序是关键**：`Times New Roman` 放第一位——浏览器按字符找字体，拉丁字母和数字它有，就它渲染；中文它没有，于是落到后面的仿宋。一条栈同时管住两种文字，不用拆 `unicode-range`。

标题字体跟配色方案走，每版内部气质统一：

| 方案 | 正文字体 | 标题字体 | 感觉 |
|---|---|---|---|
| 纸间 `paper` | Times + 仿宋 | 霞鹜文楷 | 手作、书籍感 |
| 青空 `sky` | Times + 仿宋 | 系统黑体（700） | 公文、工程感 |
| 薄荷 `mint` | Times + 仿宋 | 系统黑体（700） | 柔和、干净 |

> **为什么标题不跟正文统一**：黑体标题 + 仿宋正文是中文排版里最经典的搭配（公文就是这么排的），不打架。楷体标题 + 仿宋正文是书籍的搭配，也不打架。但楷体标题 + 黑体正文会打架——手写楷体配机械黑体，像两套设计。所以每版内部统一，不跨版混搭。
>
> **仿宋的代价**：仿宋（FangSong）是中易的商业字体，**不可再分发**，只能靠系统自带。Windows / macOS 有，Android / iOS 没有，会退到 `Noto Serif CJK SC` 之类的衬线字——观感接近但不完全一样。这是「零字体体积」的代价，接受。
>
> Logo 里的拉丁字母 `mirage wzy` 用系统无衬线即可，不必单独引字体。

### 2.2 字号阶梯

| 层级 | 字号 | 行高 | 字重 | 字间距 |
|---|---|---|---|---|
| 站点大标题 | `clamp(36px, 4.2vw, 52px)` | 1.45 | 400 | 1px |
| 页面标题 | 29px | 1.5 | 400 | 1.5px |
| 卡片标题 | 23px | 1.5 | 400 | 1px |
| 文章标题 | `clamp(26px, 3.2vw, 36px)` | 1.45 | 400 | 0.5px |
| 小标题 h2 | `21px` | 1.55 | 400 | 0.6px |
| 小标题 h3 | `17.5px` | 1.6 | 400 | 0.5px |
| **正文** | **17px** | **1.95** | 400 | 0.2px |
| 摘要 | 15.5px | 1.85 | 400 | 0 |
| 元信息 | 14px | 1.7 | 400 | 0.5px |
| 标签 | 13.5px | 1.6 | 400 | 0 |
| 代码 | 14.5px | 1.75 | 400 | 0 |

**正文行高 1.95 是刻意的**——比常规的 1.6 大不少，这是“舒服”最直接的一个来源。

正文从 16.5px 提到 17px，是因为仿宋笔画比黑体细，同字号下显得小一号。换成仿宋后 17px 才相当于原来黑体的 16.5px。

### 2.3 间距

8px 基准：

```
4  8  12  16  20  24  30  36  44  56  72  96
```

关键值：
- 页面横向留白：32px（移动端 20px）
- 内容最大宽度：**1120px**
- 正文最大宽度：**44em**（约 720px），超过就不好读了
- 卡片内边距：30px 28px 24px
- 卡片网格间距：22px
- 区块之间：76px–96px

## 3. 字体工程

### 3.1 谁要打包，谁不用

| 字体 | 用在哪 | 打包吗 | 为什么 |
|---|---|---|---|
| Times New Roman | 正文里的拉丁字母和数字 | **不用** | 系统自带（Windows/macOS 都有），macOS 上叫 Times |
| 仿宋 FangSong | 正文里的中文 | **不用** | 系统自带，但**不可再分发**（中易商业字体），只能靠系统 |
| 系统黑体 | 青空/薄荷的标题 | **不用** | 系统自带 |
| 霞鹜文楷 | **只有纸间版的标题**用 | **可能要** | 完整 TTF 24 MB，太大，必须裁剪 |

正文占页面 90% 以上的字，两种主字体都是系统的 → **正文零字体体积**，首屏不受字体影响。

霞鹜文楷只出现在纸间版的标题里，字集比正文小得多（标题就那么几个词），裁剪后体积很小。

### 3.2 方案：按实际用字裁剪（只针对霞鹜文楷）

用 `fonttools` 按站点**实际用到的字符子集化，输出 woff2。产物是发布期生成物**，放在 `static/public/assets/fonts/`，由 Nginx 直出。

```bash
# 1) 扫描模板和文章，收集所有字符
python3 tools/subset-font.py \
    assets/fonts/LXGWWenKai-Regular.ttf \
    static/public/assets/fonts/lxgw-wenkai-subset.woff2 \
    templates/ content/ static/src/

# 2) 验证覆盖
#   输出会打印「覆盖校验: 全部命中」或缺失字符列表
```

实测：345 个字符 → **24 MB 裁到 64 KB**。只用于标题时字集更小。

扫描目录必须包含 `templates/`——Go 模板是 `.html`，裁剪脚本要加上这个扩展名，否则模板里的字不会被收集（见《开发规范》§8.2）。

### 3.3 注意

- **仿宋缺失时不回退成方框**。Android / iOS 没有仿宋，会退到 `Noto Serif CJK SC` 之类的衬线字——观感接近但不完全一样。这是接受了的代价
- **emoji 不在字体里**，交给系统 emoji 字体。裁剪脚本会把 emoji 列入“缺失”属正常。
- **字体子集是发布期产物：新文章里的字在下次发布前不在子集里。这时浏览器会退回系统字体渲染，所以不会显示成方框**，只是那一两个字跟标题不是一个字体。想统一，等下次发布重裁。
- 裁剪后必须**实际渲染验证**，不能只看脚本输出。
- 加载方式：

```html
@font-face {
  font-family: "LXGW WenKai";
  src: url("/assets/fonts/lxgw-wenkai-subset.woff2") format("woff2");
  font-weight: 400;
  font-display: swap;   /* 字体没到之前先用系统字，别让文字消失 */
}
```

- `font-display: swap` + `size-adjust` 兜底，避免字体切换时版面跳动。

> **待定**：纸间版标题到底用不用霞鹜文楷？不用的话，全站零字体文件，首屏最快；用的话多背几十 KB，换一个手作感。**这个可以等做纸间版主题的时候再定**，不影响现在动手写代码——先把字体栈写进 `tokens.css`，`@font-face` 留个位置。

## 4. 信息架构

### 4.1 板块机制

核心约束：加一个板块 = 插一行数据库记录，不改代码、不重启。

板块和子页面存在 `sections` / `section_pages` 表里，通用路由 `/{section}/` 和 `/{section}/{page}/` 负责渲染。

新增板块的完整操作：
1. 后台“板块管理”→ 新增，填 slug / 标题 / 图标 / 简介 / 颜色 / 计数文案
2. 完事。导航栏、首页卡片、sitemap 自动出现

几个字段的用途：

| 字段 | 作用 |
|---|---|
| `slug` | URL 段。**有保留字**（`blog` `tags` `archive` `about` `login` `admin` `api` `s` `files` `search` 等），撞了后台会拒 |
| `in_nav` | 1 = 出现在顶栏导航。`about` 是 0——它有专门的 `/about/` 页面，导航里再列一次是重复 |
| `count_label` | 卡片右下角那行计数（手填的文案，如“7 篇”），不参与统计，留空就不显示 |
| `sort_order` | 导航和首页卡片的排序 |

如果要给板块加子页面，后台“板块 → 子页面”里加，或直接往 `section_pages` 插行。

### 4.2 板块清单

先做这三个。以后想加别的模块（读书、工具、项目之类的），后台插一行 `sections` 记录就行，导航、首页卡片、sitemap 自动跟上，代码一行不改。

| slug | 标题 | 图标 | 简介 | 计数文案 | 导航 | 子页面 |
|---|---|---|---|---|---|---|
| `notes` | 手记 | 📓 | 技术笔记、踩坑与折腾记录 | — | ✅ | — |
| `about` | 关于 | 🌸 | 我是谁，这里在折腾什么 | — | — | — |
| `guestbook` | 留言 | 💌 | 给我留句话吧 | — | ✅ | — |

`section_pages` 表和 `/{section}/{page}/` 路由先留着，板块的子页面（手记下面挂“Go 笔记”“踩坑实录”这类）随时能用。

### 4.3 导航

顶栏（sticky，backdrop-filter 模糊 14px，半透明底）：


> 本项目是**权限驱动**的：同一个 URL，不同身份看到的东西不一样。
> 差异**只体现在“多出来的东西”**，绝不影响主体的可读性和美感。
> 原则：访客永远看到一个干净、完整、能读的站点——不能因为是访客就把页面做得残缺。

> **只有两级身份**：**站长**（你，登录后）和**访客**（任何人，不注册）。

## 6. 交互与动效

原则：动效只用来解释变化，不用来表演。

| 场景 | 效果 | 参数 |
|---|---|---|
| 卡片 hover | 上浮 4px + 阴影加深 | `transform .3s cubic-bezier(.2,.8,.3,1)` |
| 卡片“去看看” | 淡入 + 左移 4px | `.3s` |
| 导航切换 | 背景色淡入 | `.22s` |
| 暗色模式切换 | 背景色/文字色过渡 | `.25s ease` |
| 滚动进场 | `opacity 0→1 + translateY 8px→0` | `.4s`，`IntersectionObserver` 触发，**只做一次** |
| 阅读进度条 | 宽度随滚动 | `transform: scaleX()`，不要改 `width`（避免重排） |
| 复制按钮 | 文字变“已复制”1.5 秒 | — |
| 对话框（分享面板） | 淡入 + 缩放 0.98→1 | `.2s`，`::backdrop` 同时变暗 |
| 上传拖拽悬停 | 虚线边框变实色 + 底色变淡 | `.15s` |
| 上传进度条 | 宽度随进度 | `transform: scaleX()` |
| 工具条展开 | 向上展开 | `.2s` |

**禁止**：视差滚动、粒子背景、自动轮播、弹跳动画、入场 stagger 超过 3 个元素。

### 6.1 暗色模式

- 切换按钮在顶栏右侧（☾），**访客也有**
- 状态存 `localStorage`（`mirage-mode` = `light` / `dark`）
- 必须在 HTML 解析前就应用，避免闪白。做法：`<head>` 里放一段内联 JS 读 localStorage 设置 `data-mode` 属性。**这段内联 JS 必须极小**（< 300 字节），因为它阻塞渲染
- 默认跟随系统：`@media (prefers-color-scheme: dark)` 在用户未手动设置时生效
- 暗色**只有一套**，不随配色方案变（见 §1.6）

### 6.2 搜索

- `/search/` 页面
- 客户端索引：`GET /search-index.json`，**由后端运行时生成**（不是构建产物）——内容随时会改，索引必须跟着变
- 索引只含**公开已发布**文章：`[{slug,title,summary,text,tags}]`
- 搜索框输入 → 前端过滤（子串匹配，标题命中权重高）
- `⌘K` / `Ctrl+K` 唤起搜索框
- 索引文件 gzip 后应该 < 30 KB（几十篇文章的量）

### 6.3 目录（TOC）

- 文章页右侧（桌面端，> 1100px 时显示）
- 从 Markdown 渲染后的 `<h2>/<h3>` 提取
- 当前所在章节高亮（`IntersectionObserver`）
- 移动端折叠到文章顶部

**目录可收缩**：

| | 桌面端 | 移动端 |
|---|---|---|
| 控件 | 目录标题右侧的折叠按钮（`›`） | 标题下方的 `<details>` |
| 收起后 | 整列隐藏，**正文重新居中**（宽度不变，只是左边距变大）；右侧边缘留一个竖排「目录」小标签，随时能拉回来 | `<details>` 合上 |
| 状态 | `localStorage`（`mirage-toc` = `on` / `off`），**翻页不丢** | 每次默认合上，不记状态 |

- 收起不是「变窄」，是**整列消失 + 正文居中**。留一条窄边反而占地方
- 状态记在 `localStorage`，不是 Cookie——这是纯界面偏好，不该进服务端
- 桌面端的收起状态**不影响**移动端（移动端每次默认合上）
- 恢复入口用竖排标签（`writing-mode: vertical-rl`）贴在右边缘中部，不跟右下角的「回到顶部」按钮打架

| ≥ 1120px | 完整布局。区块卡片 3 列。文章页显示右侧目录。 |
| 768–1119px | 区块卡片 3 列（更窄）。目录移到文章顶部折叠。 |
| 560–767px | 区块卡片 2 列。 |
| < 560px | 区块卡片 1 列。顶栏折叠为汉堡菜单。字号阶梯整体下调 1–2px。悬浮工具条改成文章顶部的一行按钮（右下角会挡住内容）。 |

**移动端注意**：
- 用户菜单收进汉堡菜单
- 分享面板用全屏 sheet，不用居中对话框
- 上传区要够大（手指点得中），拖拽在移动端不可用 → 只留“点击选择”

移动端必须检查的点：
- 代码块横向滚动不能撑破布局
- 表格横向滚动
- 触摸目标 ≥ 44×44px
- `line-height` 正文不要低于 1.9

## 8. 无障碍

| 项 | 要求 |
|---|---|
| 正文对比度 | ≥ 4.5:1（`--ink` on `--bg` 当前约 11:1，远超） |
| 强调色对比度 | 强调色作为**文字**用时需 ≥ 4.5:1。`#C26D7C` on `#F5F6F9` 约 3.6:1 → **正文里不要用强调色写小字**，只用于 ≥19px 的标题或装饰 |
| 焦点态 | 所有可交互元素 `:focus-visible` 有 2px 强调色描边 + 2px 偏移，**不能去掉 outline** |
| 图片 | 全部有 `alt`；装饰性图片 `alt=""` |
| 表单 | 每个 input 有 `<label>`；错误提示用 `aria-describedby` 关联 |
| 标题层级 | 每页 h1 唯一，h2/h3 不跳级 |
| 键盘 | 搜索框 `⌘K`；后台表单 Tab 顺序合理；后台可无 JS 使用 |
| 动效 | 尊重 `prefers-reduced-motion: reduce` → 关掉所有过渡和进场动画 |
| 对话框 | 用原生 `<dialog>`，自带焦点陷阱 + Esc 关闭 + `aria-modal` |
| 拖拽上传 | 拖拽**只是快捷方式**，必须有等价的“点击选择文件”按钮（键盘可达） |
| 文件选择 | 真实 `<input type="file">`，用 `label` 关联，**不要** `display:none` 藏掉（否则读屏器找不到） |
| 表单错误 | 错误文字用 `aria-live="polite"` 播报；输入框 `aria-invalid="true"` |
| 用户菜单 | 用 `<details>`/`<summary>` 或 `aria-expanded` 的按钮，键盘可达 |
| 私密内容 | **不要**只用颜色区分（私密角标要有文字：“私密”），色弱用户也要能读 |
| 暗色模式 | 不只是反色，重新配过色（§1.3） |

## 9. 图片

站上不需要插画，也不需要相册。技术博客里的图片基本只有两种：文章正文里的截图，和 `posts.cover` 封面图。

### 9.1 正文里的截图

- 截图放 `static/public/assets/img/`，文件名带内容哈希，和 CSS/JS 同一套发布流程
- Markdown 里直接写 `![nginx 配置](/assets/img/nginx-1a2b3c.png)`，图片路径在消毒白名单里放行站内相对路径
- 宽度不超过正文栏宽（44em），超出自动缩放
- 深色模式下图片如果底色是白的，加一圈 `--line` 描边，避免刺眼

### 9.2 封面图

- `posts.cover` 可选，填了就显示在标题下面
- 比例 21 / 9，圆角 `--r-lg`，`object-fit: cover`
- 压缩：WebP 质量 82 + JPEG 质量 85 两种格式，用 `<picture>` 让浏览器自己挑
- 每张图配一句 caption（右下角小字，`--ink-3`）

### 9.3 以后加了「养鸟」「拍照」这类板块，图片怎么放

两种走法，先用简单的：

- **图片当文章的一部分**——正文里用 Markdown 的 `![]()` 引用，图片文件丢进 `static/public/assets/img/`。一个板块写成一篇文章或者几篇，够用了
- **真要做成相册**（一个板块下几十张图，还要翻页和瀑布流）——那时候再加一张 `photos` 表，字段跟 `attachments` 类似：文件名、路径、拍摄时间、说明

第二种现在别做。板块机制保证了以后能加，但图片的表结构等到真有几十张图的时候再设计不迟。

## 10. CSS 组织

```
static/src/
├── css/
│   ├── tokens.css      设计令牌（颜色/字号/间距/圆角/阴影）
│   │                   └ 三套配色方案各一组 [data-theme="xxx"] 变量（§1.6）
│   ├── base.css        reset + 元素基础样式 + 排版
│   ├── layout.css      容器、网格、页面骨架
│   ├── components.css  卡片、标签、按钮、表格、代码块…
│   └── pages/          页面级样式（home / post / section / admin）
└── js/app.js           全部手写 JS
                     └ 配色浮层（仅站长可见，服务端按身份决定是否渲染按钮）

templates/                 Go 侧 HTML 模板（embed 进二进制）
```

发布时 CSS/JS 合并压缩 + 内容哈希，产物落到 `static/public/assets/`（`css/app.<hash>.css`、`js/app.<hash>.js`），由 Nginx 直出 `/assets/`。

**令牌命名**：`--类别-属性-变体`，全小写短横线。

```css
/* ✓ */ --ink-2  --bg-card  --r-lg  --shadow-hover
/* ✗ */ --secondaryText  --cardBg  --radiusLarge
```

**原则**：
- 样式表按“令牌 → 基础 → 布局 → 组件 → 页面”顺序引入，后者可覆盖前者
- 组件类用 `BEM` 简写：`.card` / `.card__title` / `.card--accent`
- 不写行内 `style`（除了必须动态的板块色，用 CSS 变量注入）
- 颜色**一律**用变量，禁止硬编码色值
- 响应式用 `@media` 平铺写在组件样式块内，不用 CSS 容器查询（兼容性）

## 11. 性能预算

| 项 | 预算 | 手段 |
|---|---|---|
| 首屏 HTML（gzip 后） | < 20 KB | 模板精简，不内联大段数据；服务端渲染时模板本身不要有多余空白 |
| 后台 HTML | < 30 KB | 后台可以宽松一点 |
| 服务端响应时间 | 简单页 < 30ms / 文章页 < 50ms | 模板分段缓存 + 查询加索引；渲染耗时打日志 |
| CSS（gzip 后） | < 12 KB | 单文件，minify |
| JS（gzip 后） | < 6 KB | 手写，不引框架 |
| 字体 | < 80 KB | 按字裁剪，woff2 |
| 首屏图片 | < 150 KB | 首页没有图片，文章页封面图算进去，WebP + `loading="eager"` |
| 首屏总请求数 | ≤ 5 | CSS 1 + JS 1 + 字体 1 + HTML 1（有封面图 +1） |
| 外部请求 | 0 | 不引任何 CDN |
| 静态资源 | 全在 `/assets/` 下 | Nginx 直出 + `immutable` 长缓存，文件名带内容哈希 |

没有图片的首屏更省：HTML + CSS + JS + 字体，四个请求。
