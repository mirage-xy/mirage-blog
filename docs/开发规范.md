## 0. 总则

| 原则 | 说明 |
|---|---|
| **简单优先** | 这个项目只有一个人用。所有"以后可能要"的抽象都不做。删代码比写代码容易。 |
| **标准库优先** | `net/http`、`html/template`、`embed` 能解决的一律不引第三方库。第三方库只允许：`modernc.org/sqlite`、`github.com/yuin/goldmark`、`github.com/microcosm-cc/bluemonday`、`golang.org/x/crypto`、`gopkg.in/yaml.v3`（仅 cmd/seed 用）。 |
| **显式优于隐式** | 配置项从 env 读，DB 连接从函数传入，不用全局单例（`main.go` 除外）。 |
| **错误要处理** | 不允许 `_ = err` 吞掉错误。确实可以忽略的写 `//nolint` 并注明原因。 |
| **注释写"为什么"** | 不写"做了什么"——代码本身已经说了。 |

**分层规则（不能跨层）**：

```
web ──→ store ──→ model
 │        │  ↑
 │        └──┘  依赖 perm.VisibilityFilter
 │
 └──→ perm / auth / share / render
```

- `web` 层**不允许**直接写 SQL
- `store` 层**不允许**引用 `net/http`
- `model` 层**不允许** import 任何项目内其他包（纯结构体）
- `perm` 层**不允许**碰数据库和 HTTP（保证是纯函数）
- `auth` / `share` **可以查库**（会话表、分享链接表），但**不允许**碰 `net/http`

### 1.1 配置读取规则

所有配置项都是**三级优先：命令行 flag > 环境变量 > 代码默认值**。

| 配置 | flag | 环境变量 | 默认值 | 说明 |
|---|---|---|---|---|
| 监听地址 | `-addr` | `MIRAGE_ADDR` | `127.0.0.1:8091` | 只监听回环，不对外暴露 |
| 数据库路径 | `-db` | `MIRAGE_DB` | `data.db` | 开发和生产是两份 |
| 附件目录 | `-uploads` | `MIRAGE_UPLOADS` | `uploads` | 本期不启用 |
| 静态资源根目录 | `-static` | `MIRAGE_STATIC` | `static` | 开发模式用 |
| 开发模式 | `-dev` | — | 关 | 开发模式直接提供 `static/src`，不依赖 Nginx |
| 签名密钥 | — | `MIRAGE_SECRET` | 无 | 只从环境变量读，不给 flag（命令行会进进程列表） |
| 会话有效期 | — | `MIRAGE_SESSION_TTL` | `168h` | Go 的时长格式 |

三条约定：

- **flag 只给「临时覆盖」用**（换个端口试一下），固化配置走环境变量。生产的配置在 systemd 的 `EnvironmentFile` 里
- **密钥不给 flag**。命令行参数在 `ps` 里是明文，密钥只能走环境变量或文件
- **默认值要保证最简启动能跑**：`go run ./cmd/mirage-server` 不带任何参数就该能起来

### 1.2 开发模式和生产环境的差别

只有一处：静态资源谁负责发。

| | 开发模式 | 生产 |
|---|---|---|
| 静态资源 | Go 直接把 `static/src` 发在 `/assets/` 下 | Nginx 直出 `static/public/assets/` |
| URL 形状 | `/assets/css/app.css` | `/assets/css/app.3f9a1c.css` |
| 资源名怎么解析 | `assets.Resolver` 直接拼路径 | 查构建期生成的 `manifest.json` 拿带哈希的文件名 |

模板里只写 `{{ asset "css/app.css" }}`，两种模式下的差别由 `internal/assets` 内部消化，模板不用管。

开发模式用 `-dev` 开。生产**不开**这个开关——那样 Go 会跟 Nginx 抢同一批静态资源。

## 2. Go 代码规范

### 2.1 基本

- Go 版本：`go 1.26`（`go.mod` 里写 `go 1.26.0`，是 `modernc.org/sqlite` 要求的下限）
- 格式化：`gofmt -s`（CI 里跑 `gofmt -l .` 检查）
- 所有包必须有包注释：`// Package store 提供数据访问层。`
- 导出标识符必须有注释，以标识符名开头：`// Post 表示一篇文章。`

### 2.2 命名

| 场景 | 规范 | 例 |
|---|---|---|
| 包名 | 小写单词，不用下划线 | `store` `render` `web` |
| 导出函数 | 大驼峰 | `ListPosts` |
| 私有函数 | 小驼峰 | `renderTOC` |
| 接口 | `er` 后缀 | `type Poster interface` |
| 返回错误变量 | `err` | |
| 布尔 | `is/has/should` 前缀 | `isPublished` |
| HTTP handler | `handle` 前缀 | `handlePost` |
| 表名 | 复数小写下划线 | `posts` `section_pages` |
| 列名 | 蛇形小写 | `published_at` `created_at` |

### 2.3 错误处理

```go
// ✓ 包装并附加上下文
if err := db.QueryContext(ctx, q, args...); err != nil {
    return fmt.Errorf("query posts: %w", err)
}

// ✓ 自定义错误类型
var ErrNotFound = errors.New("not found")

// ✗ 吞掉错误
if err != nil { return nil }

// ✗ 直接比较字符串
if err.Error() == "not found" { }
```

**HTTP 层错误映射**（统一在一个函数里）：

| store 返回 | HTTP | 页面 |
|---|---|---|
| `ErrNotFound` | 404 | 404 页 |
| `ErrInvalidSlug` | 400 | 400 页 |
| 其他 | 500 | 500 页 |

**日志**：用 `log/slog`，结构化输出。

```go
slog.Error("query posts", "err", err, "section", slug)
```

不要用 `fmt.Println` 打日志。

### 2.4 context

- 所有可能阻塞的函数第一个参数是 `ctx context.Context`
- 不用 `context.Background()` 在业务层，只在 `main` 和请求入口用
- 请求级 context 传给 store，store 传给 database/sql

### 2.5 并发

- Go 的 `http.Server` 自带并发处理，不需要自己起 goroutine 池
- **SQLite 的写是串行的**，所以写路径要串行化：

```go
// 写连接池固定 1
writeDB.SetMaxOpenConns(1)
```

- 任何时候都不要在事务里做：HTTP 调用、文件 IO、Markdown 渲染、JSON 编码
- 渲染顺序：先取数据 → 退出事务 → 再渲染
- **上传的文件不要在事务里写盘**：先落盘拿到 `stored_name`，再开事务写 DB；事务失败就删掉落盘的文件（补偿）

### 2.6 SQLite 连接（重要，照抄）

```go
func Open(ctx context.Context, path string) (*Store, error) {
    abs, err := filepath.Abs(path)
    if err != nil {
        return nil, fmt.Errorf("resolve db path: %w", err)
    }
    // PRAGMA 必须写进 DSN（连接级），不能是单次 Exec
    q := url.Values{}
    q.Add("_pragma", "journal_mode(WAL)")
    q.Add("_pragma", "synchronous(NORMAL)")
    q.Add("_pragma", "foreign_keys(1)")
    q.Add("_pragma", "busy_timeout(5000)")
    q.Add("_txlock", "immediate")
    dsn := "file:" + abs + "?" + q.Encode()

    readDB, err := sql.Open("sqlite", dsn)
    if err != nil { return nil, fmt.Errorf("open read db: %w", err) }
    readDB.SetMaxOpenConns(4)
    readDB.SetMaxIdleConns(4)

    writeDB, err := sql.Open("sqlite", dsn)
    if err != nil { readDB.Close(); return nil, fmt.Errorf("open write db: %w", err) }
    writeDB.SetMaxOpenConns(1)   // 写串行
    writeDB.SetMaxIdleConns(1)

    if err := readDB.PingContext(ctx); err != nil { ... }
    // 校验 WAL 真的生效（请求 WAL ≠ VFS 接受了）
    var mode string
    if err := readDB.QueryRowContext(ctx, "PRAGMA journal_mode").Scan(&mode); err != nil { ... }
    if mode != "wal" { return nil, fmt.Errorf("WAL not enabled, got %q", mode) }
    ...
}
```

> 注意：`PRAGMA` 写成 `db.Exec("PRAGMA foreign_keys = ON")` 是**错的**——它只作用于当时借出的那一条连接，池里后续新开的连接没开外键。所有连接级 PRAGMA 一律写 DSN。

## 3. 数据库规范

### 3.1 迁移

**迁移不是搬数据，是管表结构的版本。**

站上的数据从零开始，但表结构会一直变：今天建 `posts` 表，十天后加 `reading_minutes`，二十天后加 `cover`，三十天后加索引。每一次改结构都是一次迁移。

写进迁移文件的好处有三个：改错了能回退、部署时 schema 和代码对得上、三个月后看 `ls migrations/` 就知道这张库是怎么长出来的。

所以第一条迁移的内容就是「建表」，不是「导数据」。

- 迁移文件放仓库根的 `migrations/`，命名 `NNN_description.sql`（三位序号）
- 用 `embed.FS` 打进二进制，启动时自动执行未应用的迁移
- `//go:embed` 只能嵌入“当前包目录及其子目录”下的文件。所以 embed 指令要写在 `migrations/migrations.go`（`package migrations`）里；写在 `cmd/mirage-server/main.go` 里是嵌不到仓库根的 `migrations/` 的，编译会直接报 "pattern migrations: no matching files found"
- 已应用的版本记在 `schema_migrations` 表里，这张表由迁移器自己建（`CREATE TABLE IF NOT EXISTS`），不写在迁移文件里
- **迁移只增不改**：已发布的迁移文件永不修改，要改就加新文件
- 迁移必须在事务里执行（DDL 在 SQLite 里是事务性的，失败会整体回滚，不会留下半截 schema）
- 迁移失败时服务**拒绝启动**，不带着半截 schema 继续跑

### 3.2 SQL 规范

- 关键字和函数名**大写**（`SELECT`, `COUNT`, `MAX`）
- 表名、列名**小写下划线**
- 每个字段后必须有空格再写类型（`id INTEGER`）
- 缩进 4 空格
- 复杂查询先写 CTE 或拆成多个简单查询
- **所有列表查询必须 LIMIT**，即使是有分页的：

```sql
-- ✓
SELECT id, slug, title FROM posts
WHERE status = 'published'
ORDER BY published_at DESC
LIMIT 50;
```

- 避免 `SELECT *`，明确列出字段
- 字符串拼接用占位符，**绝不**拼进 SQL：

```go
// ✓
db.QueryContext(ctx, "SELECT * FROM posts WHERE slug = ?", slug)
// ✗
db.QueryContext(ctx, "SELECT * FROM posts WHERE slug = '"+slug+"'")
```

- 事务里只用 `tx.QueryContext` / `tx.ExecContext`，**不要**用 `db.*`（会跑到别的连接上，事务失效）

### 3.3 索引

- 每个表至少一个索引覆盖常用的 `WHERE` + `ORDER BY` 组合
- 新增字段后检查是否需要新索引
- 用 `EXPLAIN QUERY PLAN` 验证，**不要**凭感觉加索引

### 3.4 备份（本期不做）

**不做定时备份，这是有意接受的风险。**

先把边界说清楚：**git 里是代码和文档，没有数据库**。`.db` 是二进制、每次内容都变，被 gitignore 了。文章写完只在 `data.db` 里——服务器磁盘坏了、或者误删了库，git 的历史救不回来。

唯一的例外是：文章在**本地写成 Markdown 文件**再导入的，那 git 里天然有副本。

真要备份的时候用这个（**不能裸拷**，WAL 模式下会拷到缺数据的库）：

```bash
# ✓ 正确：用 SQLite 自己的备份能力
sqlite3 /var/lib/mirage/data.db "VACUUM INTO '/var/backups/mirage-$(date +%F).db'"

# ✗ 错误：裸拷，会丢 WAL 里的事务
cp /var/lib/mirage/data.db /var/backups/
```

备份后要跑 `PRAGMA integrity_check;` 验证。恢复的时候记得删掉残留的 `data.db-wal` 和 `data.db-shm`。

## 4. HTTP 层规范

### 4.1 路由

用 Go 1.22+ 的 `ServeMux` 模式，**不引框架**：

```go
mux.HandleFunc("GET /blog/{slug}/", h.handlePost)
mux.HandleFunc("GET /login/", h.handleLoginPage)
mux.HandleFunc("POST /login/", h.handleLogin)
mux.HandleFunc("GET /{section}/", h.handleSection)
mux.HandleFunc("GET /{section}/{page}/", h.handleSectionPage)
```

- **通配路由放最后注册**（`ServeMux` 按具体度匹配，注册顺序其实不影响结果，但读起来清楚）
- `{slug}` 只匹配**一段**（不含 `/`）。要匹配多段用 `{path...}`
- 方法写进模式（`"GET /..."`），不要在 handler 里手工判断 method
- 路径参数用 `r.PathValue("slug")` 取，**不要**自己解析 URL
- 板块 slug 是保留字（`blog` `tags` `archive` `about` `login` `logout` `admin` `api` `s` `files` `search` `assets` `healthz` 等），后台新建板块时必须校验，否则通用路由会跟专用路由打架

### 4.1.5 中间件顺序（固定）

```go
mux.Handle("GET /", chain(
    recoverMW,        // 1. panic 兜底
    logMW,            // 2. 访问日志
    loadUserMW,       // 3. 从 Cookie 查 session → 挂到 ctx
    rateLimitMW,      // 4. 限流（按 IP）
    handler,
))
```

**当前用户怎么传**：

```go
type ctxKey struct{}

// 中间件里
u, err := s.auth.CurrentUser(r)     // 未登录返回 nil, nil
if u != nil {
    r = r.WithContext(context.WithValue(r.Context(), ctxKey{}, u))
}

// handler 里
u := web.UserFrom(r.Context())       // 未登录返回 nil
```

> **不要**在每个 handler 里各自解析 Cookie——那样一定会有人漏掉某处，导致某条路径变成“未登录也能访问”。

**真实 IP 怎么取**（限流和日志都靠它）：

服务在 Nginx 后面，`r.RemoteAddr` 恒为 `127.0.0.1`，所以要读 `X-Real-IP`。只认 `X-Real-IP`，不认 `X-Forwarded-For`——后者是可伪造的请求头累加值。

```go
func clientIP(r *http.Request) string {
    if v := r.Header.Get("X-Real-IP"); v != "" {
        if ip := net.ParseIP(v); ip != nil {
            return ip.String()
        }
    }
    host, _, _ := net.SplitHostPort(r.RemoteAddr)
    return host
}
```

前提是 Nginx 那边写的是 `proxy_set_header X-Real-IP $remote_addr;`（覆盖，不是累加），并且服务只监听 `127.0.0.1`——外面连不到 8091。

**中间件不要做的事**：
- 不要在中间件里写业务逻辑
- 不要在中间件里 `http.Error` 之后还继续执行（忘了 `return` 是经典 bug）

### 4.2 响应

- Content-Type 明确写：`text/html; charset=utf-8`
- HTML 响应加 `Content-Security-Policy`（见 §6.3）
- JSON 响应加 `X-Content-Type-Options: nosniff`
- 状态码：200 / 201 / 400 / 401 / 403 / 404 / 405 / 429 / 500
- 重定向用 `http.Redirect(w, r, url, http.StatusSeeOther)`（303，见方法后）
- **不要**手写 JSON，用 `json.NewEncoder(w).Encode(v)`

### 4.3 模板

- 模板放在仓库根的 `templates/`，用 `embed.FS` 打包
- embed 指令写在 `templates/templates.go`（`package templates`）里——同一个坑见 §3.1：`//go:embed` 只嵌当前包目录及其子目录
- 一次性 `template.ParseFS` 到内存，**不要**每请求重新解析
- 数据传给模板前**先转成视图模型**（View Model），不要把 `model.Post` 直接丢给模板：

```go
// ✓
type PostView struct {
    Title    string
    BodyHTML template.HTML   // 已经渲染+消毒过
    Tags     []Tag
}
// ✓
type Tag struct {
    Name string
    URL  string
}
```

- 模板里**不做业务逻辑**（不写 `{{ if .IsPublished }}` 这类判断），判断在 Go 侧做完
- `template.HTML` 类型只用于**已经消毒过的**内容，不要为了绕过转义随手用

### 4.4 Markdown 渲染

```go
md := goldmark.New(
    goldmark.WithExtensions(extension.GFM),
    goldmark.WithRendererOptions(
        html.WithHardWraps(),      // 单换行也换行，中文写作习惯
        html.WithXHTML(),
    ),
)

p := bluemonday.UGCPolicy()
p.AllowAttrs("id").OnElements("h2", "h3", "h4")
p.AllowAttrs("class").Matching(bluemonday.SpaceSeparatedTokens).OnElements("code", "pre")
p.AllowURLSchemes("http", "https", "mailto")
```

- 渲染后**必须消毒**，用 `github.com/microcosm-cc/bluemonday`（已列入依赖清单）。goldmark 自己不防 XSS。
- 消毒只留白名单标签；`img` 的 `src` 只允许站内相对路径或 http(s)。
- **代码块不高亮**，不引 chroma——高亮库体积大，跟“首屏 gzip < 20KB”的目标不划算。
- 提取目录：从渲染后的 HTML 里扫 `<h2 id>` / `<h3 id>`（消毒时要允许 `id` 属性，否则目录拿不到锚点）

## 5. 前端代码规范

### 5.1 CSS

- 所有颜色、字号、间距、圆角、阴影**一律用 CSS 变量**，禁止硬编码
- 组件类用 BEM 简写：`.card` / `.card__title` / `.card--accent`
- 不写行内 `style`（必须动态的用 CSS 变量注入）
- 响应式断点平铺写在组件样式块内
- 尊重 `prefers-reduced-motion`：

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .01ms !important;
    transition-duration: .01ms !important;
  }
}
```

### 5.2 JavaScript

- **原生 JS，无框架，无构建**。全部放在一个文件里（`static/js/app.js`），不模块化（除非超过 1000 行）
- 用 `defer` 加载
- 所有 DOM 查询前确认元素存在
- 事件监听用 `addEventListener`，不用内联 `onclick`
- 暗色模式那段内联 JS 放在 `<head>`，**必须 < 300 字节**
- 不要用 `innerHTML` 插入用户内容（XSS）

### 5.3 模板里的资源引用

- 静态资源用 `{{ asset "css/app.css" }}` 这类辅助函数：它读发布产物目录里的文件，把内容哈希拼进文件名，输出 `/assets/css/app.3f9a1c.css`
- 哈希资源在 Nginx 上配 `immutable` 长缓存（见《项目说明文档》§8.3）
- 静态资源只有一个前缀 `/assets/`。字体、图片、CSS、JS 都在 `static/public/assets/` 下，不另开 `/_fonts/`、`/css/`
- 模板和 `migrations/` 用 `embed.FS` 打进二进制，静态资源不进——它们由 Nginx 直出

## 6. 安全规范

### 6.1 密码与会话

**密码**：
- 哈希用 `bcrypt`，**cost ≥ 12**
- 哈希串**永不返回给模板**，model 层就要挡住
- 改密码要重新哈希并**吊销该用户所有会话**（目前只有一个用户，但逻辑照样写对）
- 最小长度 8 位；不强制复杂度规则（复杂度规则只会让人写 `Password1!`）

**会话**：
- session id 用 `crypto/rand` 读 32 字节，hex 编码
- Cookie **只存 session id，不存用户信息 → 服务端查表 → 可随时吊销**
- Cookie 属性：`HttpOnly` + `SameSite=Lax` + `Secure`（有 HTTPS 时）+ `Path=/`
- 过期会话由后台定时任务清理（每小时一次）
- 登录成功时**轮换 session id**（防会话固定攻击）

```go
// ✓
func newSessionID() (string, error) {
    b := make([]byte, 32)
    if _, err := rand.Read(b); err != nil {
        return "", fmt.Errorf("read random: %w", err)
    }
    return hex.EncodeToString(b), nil
}
```

**登出**：删 `sessions` 记录 + 清 Cookie。两步都要做。

### 6.2 权限判定

**唯一入口**：`internal/perm.Can(user, action, resource)`。

```go
// ✓ 所有权限判断都走这里
if !perm.Can(u, perm.ActionWrite, perm.ResOf(p)) {
    http.Error(w, "forbidden", http.StatusForbidden)
    return
}
```

**只有两级身份，判定很简单**：

```go
func Can(user *model.User, a Action, r Resource) bool {
    if user == nil {              // 访客
        return a == ActionRead &&
            r.Visibility == model.VisibilityPublic &&
            (r.Type != "post" || r.Status == model.StatusPublished)
    }
    if user.Status == model.UserDisabled {
        return false              // 账号被停用，Cookie 还在也不算
    }
    if user.Role == model.RoleOwner {
        return true
    }
    return false                  // 未来的普通用户
}
```

> `sections` / `section_pages` 没有草稿概念，它们的 `Resource.Status` 恒为 `published`，
> 所以上面只对 `post` 额外检查 `status`。

> 以后加“普通用户”时，只需在这个函数里插一条判断（登录用户可读 `members`），
> **其余代码一行都不用动**——这就是把权限收口到一个纯函数的价值。

**硬性规则**：

| 规则 | 原因 |
|---|---|
| 模板里**禁止**出现任何权限判断 | 判断散落 → 逻辑重复 → 迟早漏一处 → 越权 |
| 权限判断**只做一次**，在 handler 里算好，塞进 View Model | 模板只管渲染 |
| `perm` 包**不许** import `store` 或 `net/http` | 保证是纯函数，好测好推理 |
| 数据查询必须**带可见性过滤** | 只在 UI 隐藏不算权限，数据不能被查到 |

**查询可见性**——在 `store` 层用参数化条件，不要手拼 SQL 字符串：

```go
// store/posts.go
func (s *Store) ListPosts(ctx context.Context, v perm.VisibilityFilter) ([]model.Post, error) {
    // v.SQL() 返回固定几种安全片段之一，绝不来自用户输入
    rows, err := s.Read.QueryContext(ctx, `
        SELECT id, slug, title, summary, body_md, section, tags, cover, status, visibility, published_at, created_at, updated_at
        FROM posts
        WHERE `+v.SQL()+`
        ORDER BY published_at DESC, sort_order DESC
        LIMIT 200`, v.Args...)
    ...
}
```

> 注意：`v.SQL()` 只能返回**代码里写死的几种片段（`status='published' AND visibility='public'` / `status='published'` / `1=1`），永远不接受用户输入拼接**。这是防 SQL 注入的最后一道闸。
>
> 另外：站长视角那条 `1=1` 会让 SQLite 走全表扫描。数据量大了以后改成**不带 WHERE 的独立查询**（同样的 SELECT，不拼条件），别让优化器去判断 `1=1` 是常量。

### 6.3 CSRF

**登录用户（管理操作）**：

- 所有 `POST` 表单带隐藏字段 `csrf_token` 和 `csrf_at`
- token = `HMAC-SHA256(SECRET, session_id + "|" + form_action + "|" + csrf_at)`
- 服务端重算并比对，不匹配返回 403
- `csrf_at` 是签发时的 Unix 秒，超过 4 小时视为过期
- Cookie `SameSite=Lax` 兜底，不作为唯一防线

**匿名用户（分享密码）**：

- 服务端渲染表单时生成一个随机值，同时写进匿名 cookie（`HttpOnly` + `SameSite=Lax`）和隐藏字段
- 隐藏字段 = `HMAC-SHA256(SECRET, "anon:" + cookie值 + "|" + form_action)`
- 提交时校验：cookie 存在、cookie 值与签名都对得上，否则 403
- 说清楚边界：这只挡“没带 cookie 的裸 POST”和“别的站直接发过来的表单”，**挡不住同源伪造**——匿名用户没有身份可盗。真正的防刷靠蜜罐 + IP 限流（§6.7）

### 6.4 文件上传（本期不实现，规格先定下）

> 注意：**本期不写上传代码。** 只留 `attachments` 表 + `internal/attachment` 包的接口形状。
> 等真有东西要存再按下面的规格实现。规格先定清楚，将来动手时不用重新设计。

**三条铁律**：

1. **磁盘文件名绝不用原始文件名。** 用 `sha256(content)` 前 32 位 + 扩展名：
   ```go
   hash := sha256.Sum256(chunk)   // 或整文件 hash
   storedName := hex.EncodeToString(hash[:16]) + ext
   ```
   → 天然防路径穿越、防同名覆盖、防信息泄露
2. 必须流式写盘，绝不 `ReadAll`。
   ```go
   // ✓
   r, _, err := r.FormFile("file")
   defer r.Close()
   dst, err := os.Create(filepath.Join(uploadDir, storedName))
   defer dst.Close()
   if _, err := io.Copy(dst, r); err != nil { ... }
   ```
   ```go
   // ✗ 32MB 文件会吃 32MB 内存，10 个并发就爆了
   b, _ := io.ReadAll(r)
   ```
3. **下载时必须重新做权限校验。** 附件的可见性 = 宿主内容的可见性。
   ```go
   // handler_file.go
   att, err := s.store.GetAttachment(ctx, id)
   host, err := s.store.GetOwner(ctx, att.OwnerType, att.OwnerKey)   // 宿主
   if !perm.Can(u, perm.ActionRead, perm.ResOf(host)) {
       http.Error(w, "forbidden", http.StatusForbidden)
       return
   }
   ```
   > 知道 URL 不等于有权下载。 私密附件必须凭权限或分享链接。

**其他要求**：

| 项 | 规则 |
|---|---|
| 大小限制 | 请求体 ≤ 32MB（`http.MaxBytesReader`）；`client_max_body_size` 在 nginx 的 server 和 location **两处**都要写 |
| 扩展名白名单 | 图片 `.png .jpg .jpeg .gif .webp .avif`；文档 `.pdf .md .txt .doc .docx .xls .xlsx .ppt .pptx`；压缩 `.zip .tar .gz`；其余拒绝 |
| MIME 校验 | 读文件头判断真实类型，**不信** `Content-Type` 和扩展名 |
| 总量配额 | 站点总附件 ≤ 10GB，超了拒绝上传并提示 |
| 原始文件名 | 只存 DB 供展示，输出时 **HTML 转义**（可能含 `<`、`"`） |
| 预览 | 只有 `image/*` 和 `application/pdf` 走内联预览，其余强制下载（`Content-Disposition: attachment`） |
| 响应头 | 下载响应加 `X-Content-Type-Options: nosniff`（防 MIME 嗅探） |
| 删除 | 删 DB 记录的同时删磁盘文件（软删 → 定时清理也可） |

### 6.5 分享链接

| 项 | 规则 |
|---|---|
| token | `crypto/rand` 32 字节 hex；**不可预测**、不可枚举 |
| 存储 | 存原文（排查方便），但**绝不能用可预测的 ID**（别用自增 id） |
| 目标 | `target_type` + `target_key` 复合键：`post:12` / `section:notes` / `section_page:studio/speeddraw` / `attachment:3`。**不要用行号存 section**——它的主键是 slug |
| 访问密码 | bcrypt 哈希存 `password_hash` |
| 有效期 | `expires_at` Unix 秒，NULL = 永久 |
| 次数 | `max_visits` NULL = 不限；**密码校验通过**后 +1（持 Cookie 的免密访问不计数） |
| 密码通过后 | 签发**绑定这条链接**的临时授权 Cookie（TTL 2 小时），避免反复输密码 |
| 授权 Cookie | 名 `mirage_share`，值 `v1.<token>.<过期时间戳>.<HMAC>`，签名内容 `share:<token>:<过期时间戳>`。**一条链接一个 Cookie，打不开别的链接** |
| 分享页 | 独立路由 `/s/{token}`，**不渲染站点导航**（避免访客以为是全站） |
| 权限 | **只读**。本期没有评论，所以不需要 `permission` 字段；将来加评论时再加一条迁移 |
| 作废 | 提供 revoke 接口，作废后立即失效 |
| 密码试错 | 同一 IP 对同一 token 每小时最多 10 次 |
| **不要** | 在分享页泄露“这个内容属于哪个板块/其他附件”等元信息 |

### 6.6 输入处理

| 输入 | 处理 |
|---|---|
| URL slug | 正则白名单 `^[a-z0-9]+(-[a-z0-9]+)*$`，不匹配返回 400；再查一遍保留字表（§4.1） |
| 标题 / 摘要 | 长度上限（标题 200 / 摘要 500），**存原文、输出时转义** |
| 板块 / 子页面标题 | ≤ 100 字符 |
| 板块简介 / 子页面简介 | ≤ 200 字符 |
| 板块计数文案 | ≤ 20 字符 |
| 访客标识 | 只存 `sha256(ip + UA + 盐)`，用于防刷。**不收邮箱**——站上没有邮件通知功能，存了也没用（评论本期不做，见 §6.7） |
| URL 字段 | 必须 `http://` 或 `https://` 开头，否则丢弃 |
| Markdown | 渲染后消毒（白名单：p/ul/ol/li/h1-h6/code/pre/blockquote/a/img/table/…） |
| 密码 | 上限 128 字节（防 bcrypt 超长截断） |
| 标签 | 每项 ≤ 30 字符，最多 10 个 |
| 站点设置标签 | 每项 ≤ 20 字符，最多 10 个 |

### 6.7 评论（本期不做）

**本期不开评论区。** 表、接口、页面都不做。

真要开的时候，按这个思路来（见《决策记录》D6）：

- 表：`comments`（`post_id` / `parent_id` / `author_id` / `guest_name` / `guest_hash` / `content` / `status` / `created_at`），`status` 三档 `pending` / `approved` / `spam`
- 三层防垃圾：
  1. **蜜罐字段**：表单里放 `name="website_url"` 的隐藏字段（CSS 藏起来 + `autocomplete="off"`），机器人填了真实值就丢弃
  2. **IP 限流**：同一 IP 60 秒内最多 3 条
  3. **访客评论一律待审**：`status='pending'`，站长在后台放行后才对访客可见；站长的评论即时显示
- 访客必须填昵称（≤ 50 字符），**不收邮箱**——站上没有邮件通知功能，存哈希也用不上
- 只存 `sha256(ip + UA + 盐)` 用于防刷
- 楼中楼最多两层

### 6.8 安全响应头

在 Nginx 的 `server` 块里（注意 `add_header` 的覆盖问题，每个 location 都要 include 同一个 snippet）：

```
X-Content-Type-Options: nosniff
X-Frame-Options: SAMEORIGIN
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: geolocation=(), microphone=(), camera=(), interest-cohort=()
Cross-Origin-Opener-Policy: same-origin
```

> `style-src` / `script-src` 的 `'unsafe-inline'` 是为了支持暗色模式的内联脚本。如果能改成 nonce 更好。

**Go 侧也要设**（防止绕过 Nginx 直连 8091）：

```go
w.Header().Set("X-Content-Type-Options", "nosniff")
w.Header().Set("Referrer-Policy", "strict-origin-when-cross-origin")
```

### 6.9 路径安全

- **绝不**用用户输入拼文件路径
- 读附件时的磁盘路径由数据库里的 `stored_name` 拼，不从 URL 取
- 拼完 `filepath.Clean` + 校验 `strings.HasPrefix(abs, uploadDir)`
- 本项目没有富文本图片上传（图片是发布期放进 `static/public/assets/` 的），若以后加，同 §6.4 的规则

### 6.10 不许做的事

- ❌ 把 `password_hash` / `token` / `session_id` 写进日志
- ❌ 在模板里判断权限
- ❌ 在 handler 里写 `u.Role == "owner"`（权限判断只走 `perm.Can`）
- ❌ 在 SQL 里拼用户输入
- ❌ 用原始文件名落盘
- ❌ `io.ReadAll` 读上传文件
- ❌ 附件下载不做权限校验
- ❌ 用可预测的分享 token
- ❌ 用一个 Cookie 打通所有分享链接
- ❌ 把 `MIRAGE_SECRET` 提交进 Git

## 7. 错误处理与日志

```go
// 请求日志中间件
func logMiddleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        start := time.Now()
        rec := &statusRecorder{ResponseWriter: w, status: 200}
        next.ServeHTTP(rec, r)
        slog.Info("http",
            "method", r.Method,
            "path", r.URL.Path,
            "status", rec.status,
            "bytes", rec.bytes,
            "dur_ms", time.Since(start).Milliseconds(),
            "ip", clientIP(r),
        )
    })
}
```

- **不要记录**：Cookie、Authorization、后台口令
- 500 错误记完整堆栈（`slog` 的 `slog.Error` 不带堆栈，需要 `debug.Stack()`）
- 日志只写 stdout，不自己写文件。生产由 systemd 的 journald 收，它自带按大小和按时间轮转，不用另外配 logrotate

### 8.1 发布

先把两件事分清：

- 内容改动即时生效——后台改完文章，刷新前台就是新的，中间没有任何构建步骤。
- 静态资源是发布期产物——字体子集、图片压缩、CSS/JS 哈希化都在 `make build` 时做一次，产物进 `static/public/assets/`。

### 8.2 字体裁剪脚本注意事项

`tools/subset-font.py` 要自己写。`mirage.tar.gz` 的 `tools/` 里有一份旧会话沙箱里写的版本，可以当起点，但直接拿到自己机器上跑不起来，接手时先改三处：

1. Node 路径是硬编码的：脚本里写着 `/workspace/.node/node-v24.22.1-linux-x64/bin/node` 和 `/workspace/.shot/node_modules/wawoff2`。自己机器上要么装 brotli 让 fonttools 直接出 woff2（`pip install "fonttools[woff]"`），要么把这两行换成自己机器上的 node 和 wawoff2 路径。
2. 默认扫描目录是 `/workspace/astro-site/src`：改成 `templates/ content/ static/src/`。
3. 扩展名漏了 `.html`：脚本只扫 `.astro .md .mdx .ts .json .txt .css`，Go 模板是 `.html`，不在列表里 → 模板里出现的字不会被收集 → 裁出来的字体一定缺模板用字。

其余注意：

- 脚本要逐个验证裁剪后的字形覆盖，缺失字符要打印出来
- emoji 缺失是正常的（走系统 emoji 字体）
- 裁剪后必须实际渲染验证（打开页面看有没有方框），不能只看脚本输出
- 缺字不会变成方框，只会让浏览器退回系统字体（见 §8.1）

```bash
curl -I http://www.miragewzy.online/
```

**纪律**：
- nginx 任何改动前**必须** `cp -a` 备份
- 改完**必须** `nginx -t` 通过才 reload
- 当前 `sites-available/mirage` 是**占位版**，新站上线时替换其内容（`location /` 改 `proxy_pass http://127.0.0.1:8091;`）

### 8.4 回滚

```bash
# 二进制回滚
sudo cp -a /usr/local/bin/mirage-server.bak /usr/local/bin/mirage-server
sudo systemctl restart mirage

# 静态资源回滚
sudo rm -rf /var/lib/mirage/public/assets
sudo mv /var/lib/mirage/public/assets.old /var/lib/mirage/public/assets

# 数据库回滚
sudo systemctl stop mirage
sqlite3 /var/lib/mirage/data.db "VACUUM INTO '/var/lib/mirage/data.db.rollback'"
sudo cp -a /var/lib/mirage/data.db.rollback /var/lib/mirage/data.db
# 关键：把残留的 WAL / SHM 一起删掉，否则旧库会带着旧 WAL 一起被读出来
sudo rm -f /var/lib/mirage/data.db-wal /var/lib/mirage/data.db-shm
sudo systemctl start mirage

# 整个站点回滚到占位页
#   把 sites-available/mirage 的 root 指回 /var/www/placeholder
```

## 9. Git 规范

### 9.1 分支

```
main         生产
feat/xxx     功能
fix/xxx      修复
docs/xxx     文档
```

**不要**在 main 上直接改。走 PR 合并。

**远端放 GitHub**（私有库）。服务器拉 GitHub 经常 TLS 重置（见《项目说明文档》§10 风险表），但**发布根本不让服务器拉代码**——发布是「本地 `make build` + `scp` 二进制和静态资源」，服务器上不做构建、不做 `git pull`。

本机推 GitHub 走 **SSH over 443**（`ssh.github.com:443`），因为 SSH 的 22 端口在这台机器上不通。给这个项目单独配一把 key（`~/.ssh/mirage_github`），公钥已经贴进 GitHub 账号，私钥不出门。

远端地址：`git@github.com:mirage-xy/mirage-blog.git`

`~/.ssh/config` 里的对应配置：

```
Host github.com
    HostName ssh.github.com
    Port 443
    User git
    IdentityFile ~/.ssh/mirage_github
    IdentitiesOnly yes
```

**推论**：服务器上不需要装 git，也不需要配任何 GitHub 凭据。

**另一个坑**：这台机器开了系统代理（`127.0.0.1:7897`），浏览器能上 GitHub，但 **git 不读 Windows 的系统代理**。所以 `git clone https://github.com/...` 会超时，走 SSH 就没这个问题。万一哪天改用 HTTPS 远程，得显式配 `http.proxy=http://127.0.0.1:7897`。

### 9.2 提交信息

用 Conventional Commits：

```
<type>(<scope>): <subject>

<body>

<footer>
```

type：`feat` `fix` `docs` `style` `refactor` `perf` `test` `build` `chore` `revert`


## 12. 常见坑速查

| 坑 | 症状 | 解法 |
|---|---|---|
| `PRAGMA` 写成单次 Exec | 偶发外键不生效 | 写进 DSN |
| 用 `:memory:` 测 | 随机 "no such table" | 用临时文件 |
| 事务里用 `db.*` | 事务失效，数据错乱 | 用 `tx.*` |
| 事务里做渲染 | 长时间持锁，`database is locked` | 先取数据，退出事务再渲染 |
| 裸拷 `.db` 备份 | 丢 WAL 里的事务 | `VACUUM INTO` |
| Nginx 普通 `location /assets/` | `immutable` 静默失效 | 用 `location ^~ /assets/` |
| Nginx 子层 `add_header` | 父层所有头被覆盖 | 抽 snippet，每处 include |
| 忘记裁字体 | 新字退回系统字体，观感不统一（**不是方框**） | 下次发布重跑 subset |
| 80 端口 301 到 HTTPS | CDN 回源成环 | 80 直接吐内容 |
| WAL 无限增长 | 磁盘涨、查询变慢 | 检查长读事务、及时 close Rows |
| `Rows` 不 `Close` | 连接泄漏、checkpoint 饥饿 | `defer rows.Close()` + 检查 `rows.Err()` |
| 模板里写权限判断 | 漏一处就越权 | 判断只在 `perm.Can`，结果塞 View Model |
| 列表查询没带可见性过滤 | 数据能被查到只是没显示 | 过滤条件写进 SQL |
| 附件用原始文件名落盘 | 路径穿越 / 覆盖 / 泄露信息 | 用 sha256 hash 命名 |
| `io.ReadAll` 读上传 | 32MB × 并发 = OOM | `io.Copy` 流式落盘 |
| 附件下载不校验权限 | 知道 URL 就能下私密文件 | 每次下载都查宿主内容的权限 |
| 分享 token 用自增 id | 可枚举、可爆破 | `crypto/rand` 32 字节 |
| 分享 Cookie 里直接放 token | 拿到 Cookie 就等于过了密码 | Cookie 放 HMAC 签名，绑定单个 token |
| 用 `X-Forwarded-For` 取 IP | 客户端可以伪造 | 只认 Nginx 覆盖写入的 `X-Real-IP` |
| 数据库回滚只 cp `.db` | 残留 WAL 跟新库对不上 | 回滚时一并 `rm -f data.db-wal data.db-shm` |
| `sections` 用行号当外键 | 它的主键是 slug，没有 id 可存 | 跨表引用用 slug 或复合键（`post:12`） |
| 裁字体只扫 `.md` 不扫 `.html` | 模板里的字不在字体子集里 | 扫描目录要含 `templates/`，扩展名要加 `.html` |
| 改密码不吊销会话 | 旧会话仍有效 | 改密码时删该用户全部 session |
| SQL 里拼可见性条件字符串 | 注入风险 | 只用代码里写死的片段 + 参数化 |
| 事务里写文件 | 事务长、锁等待、失败难补偿 | 先落盘，事务只写 DB，失败删文件 |
