## 3. 已经定死的（不用再讨论，除非用户主动说改）

### 3.1 架构与技术选型

| 项 | 决定 |
|---|---|
| 语言 | Go 1.26（go.mod 写 `go 1.26.0`——`modernc.org/sqlite` v1.61.0 的 go.mod 就是这么写的，只能跟着抬；本机工具链 1.26.5） |
| module | `mirage` |
| HTTP | 标准库 `net/http` + Go 1.22+ `ServeMux` 方法路由（`mux.HandleFunc("GET /healthz", ...)`） |
| 模板 | 标准库 `html/template` |
| 依赖 | 只有 5 个：`goldmark`、`bluemonday`、`modernc.org/sqlite`、`golang.org/x/crypto/bcrypt`、`gopkg.in/yaml.v3`（仅 seed） |
| 不引 | Web 框架、ORM、模板引擎、session 库、前端框架、CDN、代码高亮库 |
| 数据库 | SQLite，WAL + `busy_timeout` + 两条独立 `*sql.DB`（读池 4 / 写池 1）+ `BEGIN IMMEDIATE` |
| Markdown | goldmark 渲染 → bluemonday 消毒 |
| 身份 | 只有两级：站长 + 访客。**没有注册、没有普通用户、没有角色管理** |
| 评论 | **本期不做**（D6/D16），表、接口、页面全撤 |
| 附件 | 本期只留表结构和接口，不实现上传（D11） |
| 分享链接 | 授权 Cookie 绑定单个 token（D13）；`max_visits` 限的是「密码校验通过」次数 |
| 静态资源 | 全部 Nginx 直出 `/assets/`；`embed.FS` 只装 templates + migrations（D12） |
| 日志 | 只写 stdout，结构化 slog，轮转交给 journald |

**两条硬约束**：

- **所有 PRAGMA 必须写进 DSN**。写成一次 `db.Exec("PRAGMA ...")` 只对当时借出的那一条连接生效，连接池里后来开的连接全都没开。
- **`//go:embed` 只能嵌入「当前包目录及其子目录」下的文件**。所以 `migrations/` 和 `templates/` 各自单开一个 package 来放 embed 指令。

**迁移机制**（D20）：`migrations/NNN_description.sql` + `schema_migrations` 表记版本，只增不改，事务里执行，开发和生产都自动跑，失败**拒绝启动**。

> **迁移不是搬数据，是管表结构的版本。** 表结构会一直变（加字段、加索引），每一次改结构都是一次迁移。第一条迁移的内容就是建表。

### 3.2 数据与接口契约

**通用约定**（§5.0）：

- 时间统一 Unix 秒整数
- 分页 `?page=N&per_page=M`（默认 20，上限 100），响应统一 `{items, page, per_page, total, has_more}`
- 错误统一 `{"error":{"code","message"}}`；后台表单错误直接渲染回表单，带字段级提示
- 状态码 200/303/400/401/403/404/409/429/500；写操作 303 跳回（POST-redirect-GET）
- URL 页面一律带尾斜杠，`/blog/x` 自动 301；静态资源不带
- HTML `Cache-Control: no-cache`，静态资源由 Nginx 发 `immutable`
- 板块 slug 保留字（撞了后台会拒）：`blog tags archive about login logout admin api s files search assets healthz sitemap.xml rss.xml robots.txt search-index.json`

**排序与计数**：

- 文章一律 `published_at DESC, id DESC` 兜底，保证顺序稳定
- 上一篇/下一篇**只算已发布且公开的**，私密文章不参与（否则会泄露私密文章的存在）
- 对外显示的计数（标签的文章数、归档每组文章数）只统计 `published + public`

**权限模型**：`perm.Can(user, action, resource)` 一个纯函数，模板里禁止出现任何权限判断。判定顺序：访客（nil）只允许 read 且资源必须公开、已发布；`disabled` 账号全拒；`owner` 一律允许；其余（未来的普通用户）暂时全拒。

**settings 9 个键**：

| key | 说明 |
|---|---|
| `site_title` | 顶栏 logo、页脚 |
| `site_url` | 站点对外基础地址，RSS/sitemap/分享链接的绝对 URL 都用它 |
| `site_subtitle` | 首页副标题 |
| `site_description` | meta description、RSS |
| `site_author` | 文章署名、页脚 |
| `site_since` | 页脚起始年份 |
| `home_tags` | 首页那排标签（JSON 数组） |
| `home_status` | 首页状态文案 |
| `theme_today` | 全站配色：`auto` / `paper` / `sky` / `mint` |

**域名可后期改**：换域名改两处——`settings.site_url` + Nginx 的 `server_name`。代码里不写死域名。

**明暗和配色是两个轴，别混**（原来撞过名）：

| 轴 | 属性 | 取值 | 谁定 |
|---|---|---|---|
| 明暗 | `data-mode` | `light` / `dark` | 访客自己（☾ 按钮，localStorage `mirage-mode`） |

**服务端定配色**（关键）：按日期或 `settings.theme_today` 算出今天该用哪版，**直接渲染进 HTML**：

```html
<html data-theme="mint" data-mode="light">
```

首屏就对、不闪白，访客禁用 JS 也是对的配色。JS 只管浮层交互和明暗切换。

**优先级**：

```
个人偏好（站长的 Cookie mirage_theme，只影响他）  ← 最高
站点设置 settings.theme_today（对所有访客生效）
按日期自动（dayIndex % 3）                      ← 兜底
```

**访客没有任何配色入口**，只有站长登录后顶栏有个小色点能切。`?theme=` 参数只对登录的站长生效。配色浮层按钮由服务端按身份决定是否渲染——访客的 HTML 里连这个按钮都没有。

**正文字体栈**（顺序是关键）：

```css
--font-body: "Times New Roman", "FangSong", "仿宋", "STFangsong", "Songti SC", "Noto Serif CJK SC", serif;
--font-mono: "LXGW WenKai Mono", ui-monospace, SFMono-Regular, Consolas, monospace;
```

`Times New Roman` 放第一位——浏览器按字符找字体，拉丁字母和数字它有就它渲染，中文它没有就落到后面的仿宋。一条栈同时管住两种文字，不用拆 `unicode-range`。

## 7. 踩过的坑

**工程上的**

- 迁移不是搬数据，是管表结构的版本
- `//go:embed` 只能嵌当前包目录及其子目录 → 迁移和模板各自单开 package
- PRAGMA 必须写进 DSN，写成一次 Exec 只对当时那条连接生效
- SQLite 备份用 `VACUUM INTO`，裸拷 `.db` 会丢 WAL 里的事务
- Nginx：哈希资源必须 `location ^~ /assets/`（正则会抢走，immutable 静默失效）；`add_header` 在子层级会覆盖父层级**全部** `add_header`；80 端口不能 301 跳 HTTPS（将来接了 CDN 会成环）
- 字体缺字不会变方框，会退回系统字体
- `go.mod` 原本写 `go 1.25`，加 `modernc.org/sqlite` 时被自动抬到 `go 1.26.0`（那个包的 go.mod 就要求 1.26）；本机工具链是 1.26.5，服务器只跑二进制不受影响

**环境上的**

- 读中文必须用 read 工具，PowerShell 5.1 按 GBK 解析 UTF-8 会乱码
- 本机 git 不读 Windows 系统代理（`127.0.0.1:7897`），`git clone https://github.com/...` 会超时 → 走 SSH over 443
- 测网页用本机 Edge 无头模式：`msedge.exe --headless=new --screenshot=...`；要跑真实交互可以用 Node 的 WebSocket 直连 CDP 调试口（Node 24 自带 WebSocket，不用装 Playwright）
